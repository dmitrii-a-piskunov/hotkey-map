# Hotkey Map

Веб-приложение для просмотра и хранения игровых биндов на объёмной экранной копии клавиатуры (AULA F75, 75% ANSI, 80 клавиш) и мыши. Бинды группируются по играм и профилям игроков. Данные хранятся в папке на диске пользователя через File System Access API.

**Полное ТЗ:** `docs/TZ.md`. Это главный источник требований. Перед любой задачей сверяйся с нужным разделом, ссылайся на номера требований (FR-xx, NFR-xx, TC-xx).

## Стек

- TypeScript (strict, без `any`), React, Vite
- Zustand + zundo (состояние, отмена и повтор)
- Tailwind CSS + CSS-переменные для тем; 3D-вид — перспективная проекция в JS, отрисовка в SVG (без CSS 3D)
- shadcn/ui на базе Radix UI, иконки lucide-react
- Zod — схемы данных, проверка импорта, миграции
- File System Access API — основное хранение; IndexedDB (idb-keyval) — ссылка на папку и запасной режим Firefox
- vite-plugin-pwa
- Vitest, Testing Library, Playwright
- ESLint, Prettier
- GitHub Actions, GitHub Pages

Сервера нет. Всё работает в браузере.

## Команды

```bash
npm install        # зависимости
npm run dev        # dev-сервер, http://localhost:5173
npm run build      # сборка в dist/
npm run preview    # просмотр сборки
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm test           # Vitest
npm run e2e        # Playwright
```

## Структура

- `src/app` — корневой компонент
- `src/components` — клавиатура, мышь, панели, общие элементы
- `src/features` — игры, профили, бинды, группы, настройки, импорт и экспорт
- `src/domain` — типы, схемы Zod, чистая логика: конфликты, правила игры, миграции, слияние
- `src/storage` — интерфейс `StorageAdapter` и реализации `FileSystemStorage`, `IndexedDbStorage`
- `src/layouts` — раскладки устройств (`aula-f75.ts`, мышь): геометрия и подписи
- `src/styles/device-theme.ts` — цвета, размеры, подписи и параметры 3D устройств
- `src/presets` — заготовки `dota2.json`, `pubg.json`
- `src/i18n/ru.ts` — все строки интерфейса
- `tests`, `e2e` — тесты
- `docs` — ТЗ и заметки

## Ключевые правила

- Клавиши определяются по `KeyboardEvent.code`, а не по символу.
- Логика предметной области — чистые функции в `src/domain`, покрыты тестами (цель — от 70%).
- Компоненты не обращаются к хранилищу напрямую, только через store и `StorageAdapter`.
- Раскладка клавиатуры — данные, а не разметка: новая модель добавляется файлом.
- Все тексты интерфейса — на русском, только в `src/i18n/ru.ts`.
- Схема `data.json` имеет `schemaVersion`; любое изменение схемы — с миграцией и тестом.
- Всё должно работать и в Firefox, а не только в Chrome (NFR-07): это основной браузер автора. Единственное принятое исключение — Firefox не даёт отменить уход «Назад»/«Вперёд» по боковым кнопкам мыши. Для файлов — запасной режим хранения (FR-23).
- Не добавляй функции вне MVP (раздел 4.3 ТЗ). Новые идеи — в «Открытые вопросы» или «Планы развития».

## Как работать

- Делай небольшие законченные шаги по плану из раздела 16 ТЗ. После каждого шага: lint, typecheck, тесты.
- Перед крупной задачей коротко опиши план и дождись подтверждения.
- Если требование в ТЗ неоднозначно — спроси, не додумывай.
- Коммиты по Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. Ветка `main` всегда рабочая.
