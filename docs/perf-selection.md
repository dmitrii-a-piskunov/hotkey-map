# Скорость выделения клавиш (NFR-02)

Замер: `npm run perf` (`e2e/perf/selection.perf.ts`). Заготовка Dota 2, профиль «Тестовый» (~80 биндов), окно 1920×1080, панель 800 px.

- **Рамка:** 4 прохода по 60 движений указателя по всей клавиатуре и мыши, туда и обратно. Длительность кадров считается по `requestAnimationFrame`, потому что Firefox не знает `longtask`.
- **Клавиши:** Ctrl+A, Shift+стрелки и клик (режим «Навигация»). Время — от нажатия до отрисованного кадра.
- **Цель:** ни одного кадра дольше 50 мс, ответ на любое действие не дольше 50 мс.

Цифры зависят от машины, поэтому замер не входит в `npm run e2e`. Сравнивать нужно «до» и «после» на одной машине. Собранную версию можно замерить в Firefox: `npm run build`, `npx vite preview`, затем `PERF_URL=http://localhost:4173/hotkey-map/ npm run perf -- --project=firefox`.

## До оптимизации (a551787, dev-сервер)

| | Chromium 3D | Chromium 2D | Firefox 3D | Firefox 2D |
|---|---|---|---|---|
| Рамка: самый долгий кадр, мс | 117 | 117 | 201 | 194 |
| Рамка: p95 кадра, мс | 50 | 33 | 97 | 97 |
| Рамка: кадров дольше 50 мс | 12 | 8 | 141 | 130 |
| Ctrl+A, мс | 115 | 166 | 296 | 303 |
| Shift+стрелка, мс | 132 | 148 | 124 | 116 |
| Клик, мс | 58 | 47 | 69 | 90 |

Собранная версия, Firefox: рамка — самый долгий кадр 49–56 мс, 0–1 долгих кадров; Ctrl+A 88–92 мс, Shift+стрелка 39–40 мс, клик 34–41 мс.

**Куда уходило время** (трассировка Chrome и счёт рендеров React):

- Почти всё время — JavaScript в `pointermove`: 3,6 с из 5 с. Раскладка заняла 61 мс, стили 26 мс, отрисовка 158 мс.
- Около 70 % рендера React — панель. При каждом изменении выделения перерисовывались строки всех выделенных клавиш, а в каждой строке был полный Radix `DropdownMenu`, даже закрытый.
- Клавиатура: в 2D на каждое движение перерисовывались все клавиши (memo ломали `children`). В 3D на каждое движение перерисовывались `Keyboard3D` и `Mouse` из-за состояния рамки.
- `getBoundingClientRect` у хит-боксов занял 15–18 мс за всё протягивание — это не узкое место.
