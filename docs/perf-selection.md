# Скорость выделения клавиш (NFR-02)

Замер: `npm run perf` (`e2e/perf/selection.perf.ts`). Заготовка Dota 2, профиль «Тестовый» (~80 биндов), окно 1920×1080, панель 800 px.

- **Рамка:** 4 прохода по 60 движений указателя по всей клавиатуре и мыши, туда и обратно. Длительность кадров считается по `requestAnimationFrame`, потому что Firefox не знает `longtask`.
- **Клавиши:** Ctrl+A, Shift+стрелки и клик (режим «Навигация»). Время — от нажатия до отрисованного кадра.
- **Цель:** ни одного кадра дольше 50 мс, ответ на любое действие не дольше 50 мс.

Цифры зависят от машины, поэтому замер не входит в `npm run e2e`. Сравнивать нужно «до» и «после» на одной машине. Собранную версию можно замерить в Firefox: `npm run build`, `npx vite preview`, затем `PERF_URL=http://localhost:4173/hotkey-map/ npm run perf -- --project=firefox`.

**Куда уходило время** (трассировка Chrome и счёт рендеров React):

- Почти всё время — JavaScript в `pointermove`: 3,6 с из 5 с. Раскладка заняла 61 мс, стили 26 мс, отрисовка 158 мс.
- Около 70 % рендера React — панель. При каждом изменении выделения перерисовывались строки всех выделенных клавиш, а в каждой строке был полный Radix `DropdownMenu`, даже закрытый.
- Клавиатура: в 2D на каждое движение перерисовывались все клавиши (memo ломали `children`). В 3D на каждое движение перерисовывались `Keyboard3D` и `Mouse` из-за состояния рамки.
- `getBoundingClientRect` у хит-боксов занял 15–18 мс за всё протягивание — это не узкое место.

## После шагов 1–4 (c80792f, dev-сервер)

Что сделано: разделы клавиш и строки панели под `memo`; меню бинда монтируется только при нажатии или фокусе; рамка рисуется напрямую в DOM, выделение обновляется не чаще раза за кадр и только при смене клавиш под рамкой; клавиши 2D под `memo`.

|---|---|---|---|---|
| Рамка: самый долгий кадр, мс | 83 | 33 | 90 | 111 |
| Рамка: p95 кадра, мс | 17 | 17 | 21 | 21 |
| Рамка: кадров дольше 50 мс | 2 | 0 | 3 | 3 |
| Ctrl+A, мс | 76 | 76 | 130 | 132 |
| Shift+стрелка, мс | 64 | 47 | 47 | 47 |
| Клик, мс | 44 | 45 | 55 | 42 |

Время React за два прохода рамки: 2,4 с → 0,3–0,4 с, коммитов 155 → 48–66.

Собранная версия, Firefox: на рамке ни одного кадра дольше 50 мс (самый долгий — 42–49 мс, p95 14–21 мс); Ctrl+A 78–83 мс, Shift+стрелка 31–32 мс, клик 41–46 мс.

Оставшиеся долгие кадры на рамке появляются, когда выделение становится пустым: панель заново монтирует полный список действий игры (самый тяжёлый коммит, 35–64 мс в dev). Ctrl+A долгий из-за того, что за раз монтируются разделы ~80 клавиш. Время «действие → кадр» включает ожидание двух кадров (до 33 мс), поэтому это оценка сверху.

## Если понадобится ещё быстрее

Пока не делаем: после шагов 1–4 рамка в собранной версии уже без долгих кадров. Оба варианта меняют видимое поведение, поэтому перед работой их нужно согласовать.

1. **Отложенная панель (`useDeferredValue`).** Панель берёт выделение через `useDeferredValue`, а клавиатура — напрямую. Клавиатура подсвечивается сразу, панель дорисовывается следом в прерываемом рендере и не даёт долгих кадров. Это лечит оба оставшихся места: Ctrl+A, когда монтируются разделы ~80 клавиш, и монтирование полного списка действий, когда выделение становится пустым. Видимая разница: при быстрой рамке и Ctrl+A панель отстаёт от клавиатуры на кадр-другой. Тесты, которые ждут мгновенного обновления панели, нужно перевести на ожидание (`findBy…`).
2. **Во время рамки — только «Выделено: N».** Пока рамка тянется, панель показывает лёгкий заголовок с числом выделенных входов, а полный список строится после отпускания. Это самый дешёвый вариант, но список действий во время протягивания не виден. Пробовать, если шаг 1 не поможет.
