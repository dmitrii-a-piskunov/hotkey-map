## 1. Общие сведения

### 1.1. Название и краткое описание

**Название:** Hotkey Map

**Описание:** веб-приложение, которое показывает игровые бинды на объёмной экранной копии клавиатуры и мыши пользователя и хранит их по играм и профилям игроков в папке на компьютере.

### 1.2. Предпосылки и проблема

- Бинды в играх приходится вспоминать или искать в меню настроек, где не видно, какие клавиши заняты и где конфликты.
- За одним ПК могут играть разные люди, у каждого свои привычные настройки.
- Бинды и настройки (чувствительность, FOV и т. п.) хранятся локально и теряются при смене ПК или переустановке системы.
- Готового наглядного инструмента, который показывает бинды на копии своей клавиатуры, нет.

### 1.3. Назначение

**Этап 1** — личное использование на одном ПК с Windows. Приложение открыто в отдельном окне или на втором мониторе, им пользуются перед игрой или во время паузы. Внутри одной игры можно вести профили нескольких людей. Приложение бесплатное и работает без сервера.

**Этап 2** — многопользовательский сервис для хранения и переноса биндов и конфигов игр между компьютерами (раздел 4.5).

### 1.4. Термины и сокращения

| Термин | Определение |
| --- | --- |
| Игра | Группа, внутри которой хранятся действия, контексты, категории, шаблон настроек и профили |
| Действие | Игровая команда, которую можно назначить на клавишу, например «Прыжок». Вводится вручную по меню игры |
| Контекст | Режим игры, в котором действует команда: «Пешком», «В транспорте». Особый контекст «Везде» действует во всех режимах |
| Категория | Группа действий с названием и цветом («Движение», «Бой»), по ней подкрашиваются клавиши |
| Профиль | Вариант настроек одного игрока в игре: бинды и значения настроек |
| Бинд | Связь действия с клавишей или кнопкой мыши в профиле, с учётом модификаторов и типа нажатия |
| Модификатор | Клавиша Ctrl, Shift или Alt в составе комбинации |
| Комбинация | Бинд из модификатора и основной клавиши, например Ctrl+1 |
| Слой | Режим экранной клавиатуры, который показывает бинды с выбранным модификатором |
| Тип нажатия | Как срабатывает бинд: нажатие, удержание, переключение, двойное нажатие, долгое нажатие |
| Параметр бинда | Дополнительное свойство бинда со списком значений, заданным для игры. Пример: режим каста в Dota 2 |
| Конфликт | Ситуация, когда одна клавиша с теми же модификаторами и типом нажатия назначена на разные действия в пересекающихся контекстах |
| Шаблон настроек | Список настроек игры (чувствительность, FOV) с типом и диапазоном, общий для всех профилей игры |
| Раскладка клавиатуры | Описание физического расположения клавиш конкретной модели. Не путать с языком ввода |
| Язык подписей | Какие символы подсвечены на клавишах: английские или русские |
| Папка данных | Папка на диске, выбранная пользователем, где приложение хранит свои файлы |
| PWA | Веб-приложение, которое устанавливается из браузера как программа: ярлык, своё окно, работа без интернета |
| MVP | Минимальная рабочая версия, версия 1.0 |

### 1.5. Ссылки и источники

- [AULA F75 — страница модели](https://epomaker.com/products/aula-f75-wired): 75% ANSI с регулятором. 80 клавиш, справа от пробела Fn и Ctrl, правого Alt нет.
- [File System Access API — MDN](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API): доступ к папке на диске из браузера.
- Меню настроек управления Dota 2 и PUBG: источник для заготовок действий и шаблонов настроек.

## 2. Цели, задачи и критерии успеха

### 2.1. Цель проекта

За 1–3 дня сделать приложение, в котором бинды любой игры и любого профиля видны на одном экране, на точной копии своей клавиатуры, а все настройки надёжно хранятся в файле на компьютере и переносятся на другой ПК за минуту.

### 2.2. Задачи

1. Отобразить объёмную копию клавиатуры AULA F75 и мыши с двумя боковыми кнопками.
2. Дать вести справочники игры: действия, контексты, категории, параметры бинда и шаблон настроек.
3. Дать вести несколько профилей в игре: бинды и значения настроек.
4. Показывать действия выбранных клавиш, комбинации с модификаторами и конфликты.
5. Хранить данные в папке на диске с автосохранением и резервными копиями, поддержать импорт и экспорт.
6. Заложить основу для этапа 2: отдельный слой хранения, версия схемы данных, раскладки клавиатур как отдельные файлы.

### 2.3. Учебные цели

- Сделать законченный проект на TypeScript и React.
- Освоить разработку с Claude Code от ТЗ до релиза.
- Разобраться с File System Access API, PWA и отрисовкой 3D-вида (перспективная проекция, SVG).
- Настроить CI/CD на GitHub Actions и публикацию на GitHub Pages.

### 2.4. Критерии успеха

| Критерий | Как проверить | Целевое значение |

| Перенос реальных настроек | Внести свои бинды и настройки | Профили Dota 2 и PUBG внесены полностью |
| Сохранность данных | Перезапустить браузер и ПК | Все данные на месте, ни одной потери за месяц использования |

### 3.4. Ключевые сценарии

**Сценарий 1: Первый запуск**

- **Предусловие:** приложение открыто в Chrome или Edge впервые.
- **Шаги:**
  1. Приложение показывает приветствие и кнопку «Выбрать папку для данных».
  2. Пользователь выбирает папку, браузер спрашивает разрешение, пользователь разрешает.
  3. Приложение создаёт в папке `data.json`, `icons/` и `backups/`.
  4. Приложение предлагает загрузить заготовки Dota 2 и PUBG или начать с нуля.
- **Результат:** открыт главный экран с клавиатурой, данные сохраняются в выбранную папку.

**Сценарий 2: Узнать, что на клавише**

- **Предусловие:** есть игра и профиль с биндами.
- **Шаги:**
  1. Пользователь выбирает игру и профиль в шапке.
  2. Нажимает клавишу на настоящей клавиатуре или кликает по экранной.
  3. Клавиша обводится, в панели справа появляются её действия с контекстом, категорией, типом нажатия и параметром.
  4. Ctrl+кликом добавляет ещё две клавиши, панель показывает действия всех трёх по группам.
- **Результат:** пользователь видит все действия выделенных клавиш.

**Сценарий 3: Назначить бинд**

- **Предусловие:** в игре заведены действия.
- **Шаги:**
  1. Пользователь открывает вкладку «Действия» в панели справа: список повторяет меню настроек игры.
  2. Кликает по кнопке клавиши у нужного действия, кнопка переходит в режим «Нажмите клавишу…».
  3. Нажимает клавишу или комбинацию на настоящей клавиатуре либо кликает по экранной.
  4. Приложение проверяет правила игры и конфликты, при конфликте показывает предупреждение под кнопкой.
- **Результат:** бинд сохранён, клавиша подкрашена, данные записаны в файл.

**Сценарий 4: Посмотреть комбинации с Ctrl**

- **Шаги:**
  1. Пользователь выбирает слой Ctrl в переключателе над клавиатурой или нажимает любую комбинацию с Ctrl на настоящей клавиатуре.
  2. Клавиатура показывает бинды вида Ctrl+клавиша, остальные клавиши приглушены.
  3. Кнопка «Без модификатора» возвращает основной слой.
- **Результат:** видны все комбинации с Ctrl.

**Сценарий 5: Перенос на новый ПК**

- **Шаги:**
  1. На старом ПК пользователь нажимает «Экспорт» → «Всё» и получает файл `.hotkeymap.json`.
  2. На новом ПК открывает приложение, выбирает папку и нажимает «Импорт».
  3. Приложение показывает, что будет импортировано, пользователь подтверждает.
- **Результат:** все игры, профили, бинды, настройки и иконки восстановлены.

## 4. Границы проекта и MVP

### 4.1. Входит в этап 1

- Объёмная экранная клавиатура AULA F75 и мышь с двумя боковыми кнопками.
- Игры, действия, контексты, категории, параметры бинда, шаблон настроек.
- Профили с биндами, комбинациями и значениями настроек.
- Выделение клавиш как в проводнике, группы клавиш, слои модификаторов, конфликты, поиск.
- Хранение в папке на диске, резервные копии, импорт и экспорт в собственном формате.
- Заготовки Dota 2 и PUBG.
- Темы, язык подписей, установка как PWA.

### 4.2. Не входит в этап 1

- Аккаунты, сервер, облачное хранение, общий доступ.
- Чтение и запись настоящих конфигов игр.
- Автоматическое определение модели клавиатуры и выбор других моделей в интерфейсе.
- Оверлей поверх игры и реакция на клавиши, когда окно приложения неактивно.
- Иконки из ярлыков .lnk. Ярлыки Steam (.url) — исключение: иконка по ним скачивается с CDN Steam (FR-05).
- Мобильная версия.

## 5. Выбор платформы

**Решение:** одностраничное веб-приложение (SPA), устанавливаемое как PWA, на GitHub Pages. Данные хранятся в папке на диске через File System Access API в Chrome или Edge. В Firefox работает запасной режим с хранением внутри браузера.

Почему так: приложение используется в отдельном окне, а не поверх игры, и реагирует на клавиши только когда активно — для этого не нужна программа для Windows. Веб-стек быстрее всего делается с Claude Code, бесплатно публикуется из публичного репозитория и проще всего развивается в многопользовательский сайт на этапе 2.

### 5.1. Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| Браузер, данные внутри браузера (IndexedDB) | Самый простой, работает везде | Данные теряются при очистке браузера | Только как запасной режим для Firefox |
| **Браузер + папка на диске** | Данные в файлах на ПК, без сервера, бесплатно | Только Chrome и Edge, браузер спрашивает разрешение на папку | **Выбран** |
| Браузер + локальный сервер с SQLite | Настоящая база данных | Два процесса, сервер нужно запускать | Отклонён: сложнее без выгоды на этапе 1 |
| Программа для Windows на Tauri | SQLite, иконки из ярлыков, своё окно | Нужен Rust, дольше настройка | Отложен до этапа 2 при необходимости |

**Тип:** клиентское SPA без сервера, слоистая структура.

| Слой | Ответственность | Взаимодействует с |
| --- | --- | --- |

- **Клавиши определяются по физическому коду** (`KeyboardEvent.code`, например `KeyQ`), а не по символу. Поэтому бинды не зависят от языка ввода: Q и Й — одна клавиша.

- **Раскладка AULA F75 — файл данных** `src/layouts/aula-f75.ts`. Новая модель клавиатуры — новый файл, без изменения компонентов.
- **У схемы данных есть номер версии** и функции миграции между версиями.

### 7.2. Подробное описание функций

#### FR-01. 3D-клавиатура AULA F75

- **Описание:** в центре экрана — объёмная копия клавиатуры AULA F75 (75% ANSI, 80 клавиш, регулятор справа сверху). Раскладка — в приложении А.
- **Вид:** как на превью `docs/images/device-*.png`. Камера сверху и немного со стороны пользователя: ряд с пробелом ближе и крупнее, ряд F-клавиш уходит вглубь. Клавиша — усечённая пирамида: верхняя грань со скруглёнными углами, передняя и боковые грани-трапеции; верхняя грань сдвинута наружу от центра по перспективе, наклонена по ряду профиля и не выходит за бока клавиши. Задний край бока идёт по касательной к скруглению верхней грани — без просветов и выступов. У корпуса видна толщина, регулятор — цилиндр.
- **Отрисовка 3D:** перспектива считается в JS и рисуется плоско в SVG, без CSS 3D, чтобы вид работал быстро и переключался без задержек. Подписи и обводка выделения наклоняются вместе с верхней гранью одной плоской трансформацией.
- **Тема устройств:** все цвета, размеры, подписи и параметры 3D — в `src/styles/device-theme.ts`, в компонентах и CSS значений нет.
- **Подписи:** на буквах английская слева сверху, русская справа снизу; на цифрах и символах — верхний символ, основной и русский символ; на модификаторах — значок и слово.
- **Состояния клавиши:** свободна; занята (цвет по режиму окраски, FR-30); выделена (только толстая обводка акцентного цвета); конфликт (красная обводка и значок); приглушена (в чужом слое или при поиске); отказ — у неназначаемой клавиши, пока на ней зажата кнопка мыши или пока она выделена (красная рамка и диагональная штриховка, не путается с выделением, конфликтом и цветами групп).
- **Анимация:** при нажатии клавиша проседает, длительность 80–120 мс — и от настоящей клавиатуры, и при клике мышью по клавише (пока зажата кнопка). При выделении рамкой клавиши не проседают.
- **Регулятор и Fn:** отображаются, но назначить на них нельзя: игры и браузер их не видят. Так же ведут себя непередаваемые клавиши текущей игры (FR-05), например Win, если её добавили туда для игры. Win по умолчанию назначается: нажатие забирает Windows, поэтому бинд на неё ставится кликом по экранной клавише. Пока зажата левая кнопка мыши на такой клавише, видны красная рамка, диагональная штриховка и подсказка; при отпускании они пропадают. Такие клавиши можно выделить рамкой, Shift+кликом, Ctrl+кликом и стрелками: тогда они красные (рамка и штриховка) без подсказки, пока выделены. Обычный клик их не выделяет и не снимает, клавиша не проседает; подсказка видна только при удержании кнопки мыши. Ctrl+A их не выделяет, бинды на них не назначаются. Подсказка у клавиш нижнего ряда — под клавишей, у остальных клавиш и регулятора — над ней, на одинаковом расстоянии.
- **Текст подсказки** зависит от выбранной игры: «Эта клавиша не передаётся в Dota 2». У каждой игры свой набор непередаваемых клавиш (поле «Непередаваемые клавиши», FR-05). Пока игр нет, текст общий: «Эта клавиша не передаётся в игры».
- **Переключатель 2D / 3D** в настройках приложения.
- **Расцветка клавиатуры:** переключатель в шапке — «Стандартная» (синие буквенные клавиши, серые модификаторы, жёлтые Esc, Enter, пробел и стрелки, оранжевые надписи) или «Чёрная» (все клавиши цвета серо-чёрных модификаторов «Стандартной», надписи светло-серые). По умолчанию «Стандартная», выбор запоминается. Меняются только родные цвета клавиш без биндов; окраска по категориям и группам (FR-30), выделение, конфликты, отказ, приглушение и подписи действий не меняются. Корпус, регулятор и мышь одинаковы в обеих расцветках. Работает одинаково в 2D и 3D, в светлой и тёмной теме. Цвета обеих расцветок — в теме устройств.
- **Масштаб:** клавиатура вписывается в ширину свободной области, пропорции сохраняются. Место под клавиатуру и мышь одинаковое в 2D и 3D, поэтому при переключении вида мышь не сдвигается.
- **Критерии приёмки:**
  - [ ] Расположение и размеры клавиш совпадают с реальной клавиатурой.
  - [ ] Клик по любой назначаемой клавише выбирает её.
  - [ ] В 2D и 3D видны те же состояния.
  - [ ] Расцветка меняется сразу и сохраняется после перезагрузки; цвета занятых клавиш от неё не зависят.

#### FR-02. 3D-мышь

- **Описание:** справа от клавиатуры — схематичная мышь в тех же цветах. Объёмная заливка с бликом и затемнением по контуру — в 2D и 3D (2D — вид сверху, блик посередине); в 3D добавляется перспектива, блик смещён к спинке, а перед темнее, потому что уходит вглубь. Тень — как у клавиатуры в том же виде.
- **Кнопки:** линия раздела ЛКМ и ПКМ с корпусом — дуга, выгнутая назад (как перед мыши, развёрнутый на 180°). В 3D дуга мельче, чем в 2D: она лежит на самой высокой точке корпуса. Слева от ЛКМ и справа от ПКМ — тонкая полоска корпуса постоянной ширины: внешний край кнопки — прямая вдоль бока, она доходит до переда и врезается в его закругление под углом. Выделение, нажатие и зона клика кнопки идут по её контуру.
- **Подписи:** вне корпуса, с выносками: слева Mouse 5 и Mouse 4 у боковых кнопок, справа от колеса Mouse wheel up, Mouse 3 и Mouse wheel down.
- **Назначаемые входы:** левая кнопка, правая кнопка, нажатие колеса, прокрутка вверх, прокрутка вниз, боковая кнопка «назад» (Mouse4), боковая кнопка «вперёд» (Mouse5).
- **Поведение:** как у клавиш: выбор, подсветка, цвета категорий, конфликты. Прокрутка вверх и вниз — зоны над и под колесом. Выделенная кнопка обводится по своей части контура обводкой одной толщины; если боковая кнопка заходит на кнопку корпуса, обводка огибает её с зазором.
- **Критерии приёмки:**
  - [ ] Все 7 входов выбираются кликом и принимают бинды.

#### FR-03. Режимы ввода: проверка нажатий и навигация

- **Описание:** переключатель режима ввода в шапке. Работает, когда окно приложения активно и фокус не в поле ввода. При запуске включён режим «Проверка нажатий».
- **Режим «Проверка нажатий»:**
  1. Нажатие настоящей клавиши анимирует её на экране и выделяет её одну.
  2. Нажатие с зажатыми Ctrl, Shift или Alt выделяет клавишу и переключает соответствующий слой.
  3. Модификатор, нажатый и отпущенный без других клавиш, выделяет сам себя (на Ctrl или Shift тоже бывают бинды).
  4. Нажатие колеса, кнопки мыши 4 и 5 и прокрутка над областью клавиатуры и мыши выделяют соответствующий вход. ЛКМ и ПКМ так не выделяются: они заняты выделением и меню.
- **Режим «Навигация»** (как в проводнике):
  - стрелки перемещают выделение на соседнюю клавишу или кнопку мыши по экрану; с правого края клавиатуры стрелка вправо переходит на мышь;
  - Shift+стрелка расширяет выделение в эту сторону;
  - Ctrl+A выделяет все занятые клавиши текущего слоя;
  - Ctrl+Z и Ctrl+Shift+Z отменяют и повторяют изменение (FR-24);
  - клавиши не анимируются и не выделяют сами себя.
- **Мышь** (Ctrl+клик, Shift+клик, рамка) работает одинаково в обоих режимах (FR-13).
- **Ограничения:** не перехватываются комбинации, которые забирает браузер или Windows (Ctrl+W, Ctrl+T, Ctrl+N, Alt+F4). Такие бинды назначаются кликом по экранной клавиатуре. Fn и регулятор не назначаются вовсе (FR-01); Win не перехватывается, бинд на неё — кликом. Остальные клавиши получают `preventDefault`, чтобы, например, F5 не перезагружал страницу.
- **Esc** в обоих режимах снимает выделение или закрывает диалог, отменяет захват клавиши.

#### FR-04. Язык подписей EN/RU, EN, RU

- **Режимы** — переключатель в шапке:
  - **EN/RU** — реалистичный вид, как на настоящей клавиатуре: английская подпись слева сверху основным цветом, русская справа снизу серым, на цифрах и символах — верхние символы Shift. Режим по умолчанию.
  - **EN** и **RU** — только то, что нужно для биндов: буквы выбранной раскладки, цифры и клавиши-символы показаны одним знаком по центру (в RU — Й, Х, Ж, Б, Ю, Ё и т. п.), без верхних символов Shift. Модификаторы, F-клавиши и стрелки — в привычном виде.
- **Автопереключение:** кнопка «Авто» рядом с переключателем, по умолчанию включена. В режимах EN и RU раскладка подписей следует за символом последней нажатой клавиши (нажал «й» — включается RU). Режим EN/RU выбирается только вручную и сам не меняется.

#### FR-05. Управление играми

- **Действия:** создать, переименовать, удалить (с подтверждением и числом профилей, действий и биндов — из меню выбора игры в шапке, как у профиля, или в редакторе игры), сменить иконку. Выбор игры — список с иконками в шапке.
- **Поля:**

| Поле | Тип | Обязательное | Ограничения | По умолчанию |
| --- | --- | --- | --- | --- |
| Название | Строка | Да | 1–60 символов, уникальное | — |
| Иконка | Картинка | Нет | PNG, JPG, WebP, ICO до 1 МБ, хранится как 128×128 px | Первая буква названия |
| Steam AppID | Число | Нет | Целое положительное | — |
| Клавиш на действие | Число | Да | 1 или 2 | 1 |
| Допустимые модификаторы | Набор | Да | Ctrl, Shift, Alt | Все три |
| Непередаваемые клавиши | Набор кодов клавиш | Да | Коды из раскладки и регулятор | Fn, регулятор |

- **Иконка:** перетащить картинку в область иконки, вставить из буфера обмена (Ctrl+V в диалоге), выбрать файл кнопкой, перетащить ярлык игры Steam с рабочего стола (или выбрать его кнопкой) или ввести Steam AppID и нажать «Загрузить из Steam».
- **Ярлык Steam** (`.url`) содержит `URL=steam://rungameid/<AppID>` и `IconFile=…\Steam\steam\games\<хеш>.ico`. Браузер не читает файл по этому пути, но тот же файл лежит на CDN Steam: `shared.fastly.steamstatic.com/community_assets/images/apps/<AppID>/<хеш>.ico`. Это настоящая иконка игры. Если у игры нет Steam AppID, он берётся из ярлыка.
- **«Загрузить из Steam»** по AppID показывает три варианта, пользователь выбирает кликом: квадрат из центра `header.jpg`, верх вертикальной обложки `library_600x900.jpg`, `logo.png` на тёмном фоне. Недоступные варианты не показываются.
- **Файл иконки:** `icons/<id игры>-<8 символов>.png`, при каждой замене — новое имя. Старый файл сразу не удаляется (отмена изменения вернёт ссылку на него, FR-24). При запуске удаляются файлы в `icons/`, на которые не ссылаются ни `data.json`, ни одна резервная копия; если какую-то копию прочитать не удалось, не удаляется ничего.
- **При создании** у игры автоматически появляются контекст «Везде», шаблон без настроек и профиль «Основной». Игра становится текущей, открывается редактор.
- **Непередаваемые клавиши** выбираются по рядам раскладки; Fn и регулятор отмечены всегда и не снимаются. Win в части игр назначается, поэтому по умолчанию не отмечена.
- **Критерии приёмки:**
  - [ ] Иконка добавляется всеми тремя способами.
  - [ ] Удаление игры удаляет все её данные после подтверждения.

#### FR-06. Контексты

- **Описание:** список режимов игры, вводится вручную: название (уникальное в игре) и порядок. Контекст «Везде» системный: его нельзя удалить, он пересекается со всеми и всегда стоит первым; остальные сортируются перетаскиванием.
- **Удаление контекста** с действиями — только с переносом действий в другой контекст.

#### FR-07. Категории с цветом

- **Описание:** список групп действий, вводится вручную: название (уникальное в игре) и цвет (палитра из 12 цветов или свой HEX). Порядок категорий задаётся перетаскиванием и задаёт порядок разделов в списке действий.
- **Использование:** цвет подкрашивает клавиши и метки действий в панели. Действие может быть без категории (серый цвет).
- **Удаление категории** снимает её с действий после подтверждения.

#### FR-08. Действия

- **Поля:** название (обязательно, до 80 символов), оригинальное название на английском (необязательно), контекст (обязательно, по умолчанию «Везде»), категория, описание (до 300 символов).
- **Список действий:** повторяет меню настроек игры: разделы по категориям в порядке игры, порядок действий и разделов задаётся перетаскиванием, в заготовках — как в игре. Раздел «Без категории» — последним. Перенос действия в другой раздел меняет его категорию. В каждой строке — кнопки клавиш для назначения (FR-12). Над списком — поиск; пока он заполнен, перетаскивание выключено.
- **Удаление действия** удаляет его бинды во всех профилях игры, приложение показывает, сколько биндов затронуто.

#### FR-09. Параметр бинда

- **Описание:** у игры может быть один необязательный параметр бинда: название и список значений. Пример для Dota 2: «Режим каста» — «Обычный», «Быстрый», «Быстрый при отпускании».
- **Использование:** при назначении бинда значение выбирается из списка, отображается в панели действий.

#### FR-10. Шаблон настроек

- **Описание:** список настроек игры, общий для всех профилей. Настройки объединяются в группы («Мышь», «Графика», «Звук»).
- **Поля настройки:** группа, название, тип, единица измерения, значение по умолчанию.
- **Типы:**
  - ползунок: минимум, максимум, шаг;
  - переключатель: вкл / выкл;
  - список: варианты значений; показывается выпадающим списком или кружками, как в меню игры;
  - текст: до 200 символов;
  - пояснение: текст до 500 символов в рамке, без значения — на месте картинки из меню игры (схема мини-карты, полосы здоровья).
- **Раскладка:** колонки и подразделы как в меню игры задаются в заготовках и при правке сохраняются; в редакторе — тип «Пояснение» и вид списка.
- **Изменение диапазона** ползунка приводит значения в профилях к новому диапазону и шагу, приложение предупреждает об этом до сохранения и показывает число затронутых профилей. При смене типа настройки или удалении варианта списка значения, которые к ней не подходят, сбрасываются к значению по умолчанию — тоже с предупреждением.
- **Порядок:** настройки сортируются перетаскиванием внутри группы и между группами; перенос в другую группу меняет группу настройки.

#### FR-11. Управление профилями

- **Действия:** создать, переименовать, дублировать, удалить (с подтверждением; последний профиль игры удалить нельзя).
- **Поля:** название (1–40 символов, уникальное в игре), заметки (до 1000 символов).
- **Дублирование** копирует бинды, значения настроек, заметки и группы клавиш, название — «Копия <имя>» (если занято — «Копия <имя> (2)»). Новый профиль становится текущим.
- **Где:** выбор профиля и меню «Новый профиль», «Переименовать профиль», «Дублировать», «Удалить профиль» — в шапке. Заметки — во вкладке «Заметки» панели справа (раздел 8.1). Текст сохраняется при уходе из поля, при смене профиля и при закрытии страницы, а не на каждый символ: отмена (FR-24) — одним шагом.

#### FR-12. Назначение бинда в списке действий

- **Описание:** бинды назначаются как в меню настроек игры: в списке действий у каждого действия есть кнопки клавиш. Число кнопок — по правилу игры (1 или 2). На кнопке — текущая клавиша или комбинация, например «Ctrl+1», или «—», если не назначено.
- **Где:** вкладка «Действия» в панели справа и строки действий в панели выделенной клавиши (FR-13). Поведение кнопки одинаковое.
- **Строка действия:** название, кнопки клавиш, тип нажатия и параметр (если отличаются от значения по умолчанию — показываются в строке, иначе в меню «⋯»). В списке по категориям контекст показывается, только если он не основной для игры (тот, где больше всего действий); в панели выделенной клавиши — ещё метка категории.
- **Окно «Привязка клавиши»** (как в Dota 2): клик по кнопке клавиши открывает окно у левого края панели. Окно не модальное: клавиатура и мышь на экране остаются доступны.
  1. В окне — название действия (и номер слота, если их два) и поле с текущей клавишей.
  2. Пользователь нажимает клавишу или комбинацию на настоящей клавиатуре, любую кнопку мыши (ЛКМ, ПКМ, колесо, Mouse 4/5) или прокручивает колесо над полем, нажимает кнопку мыши над изображением мыши или кликает по экранной клавише. Новая клавиша видна в поле, но ещё не сохранена. Модификаторы берутся из зажатых клавиш. Enter, Space и Tab тоже назначаются: сохраняет только кнопка.
  3. Проверяются правила игры (непередаваемые клавиши, допустимые модификаторы). Нарушение — красный текст, сохранить нельзя.
  4. Проверяются конфликты (FR-15) — до сохранения. Конфликт не блокирует: текст «Клавиша уже привязана к действию «…»» и кнопки «Всё равно привязать» и «Привязать и снять с других». Без конфликта — «Подтвердить».
  5. «Очистить» делает поле пустым; подтверждение снимает бинд.
- **«Сбросить настройки»** справа от поиска во вкладке «Действия» снимает все бинды профиля после подтверждения с их числом; значения настроек и группы клавиш не меняются.
- **Закрыть без сохранения:** Esc, крестик окна или клик вне окна, кнопок клавиш, клавиатуры и мыши. **Снять бинд:** крестик на кнопке клавиши.
- **Клик по экранной клавише в захвате:** модификаторы — зажатые Ctrl, Shift, Alt, а если ничего не зажато — модификаторы текущего слоя (в слое Ctrl клик по W даёт Ctrl+W). Так назначаются комбинации, которые забирает браузер. Пока открыто окно, сцена обведена акцентным цветом; в слое с модификатором в окне подсказка «Клик по экранной клавише назначит Ctrl+…».
- **Мышь в захвате:** ЛКМ по кнопке или зоне изображения мыши назначает эту кнопку или зону; другие кнопки мыши и прокрутка над изображением мыши назначают сами себя.
- **Тот же вход в другом слоте** этого же действия переезжает в новый слот: дважды одну клавишу действию не назначают. При замене клавиши в слоте тип нажатия и параметр сохраняются. Параметр по умолчанию — первый вариант списка.
- **В редакторе игры** (FR-08) у действий видны клавиши текущего профиля, только для чтения: захват клавиш внутри диалога невозможен.
- **Тип нажатия** (нажатие, удержание, переключение, двойное, долгое; по умолчанию нажатие) и **параметр** (если задан в игре) — свои для каждого бинда.
- **Критерии приёмки:**
  - [ ] Бинд назначается двумя кликами и одним нажатием клавиши.
  - [ ] Кнопок у действия ровно столько, сколько разрешает правило игры.
  - [ ] Комбинация Ctrl+1, нажатая в режиме захвата, сохраняется как Ctrl+1.

#### FR-13. Выделение клавиш и панель действий

- **Выделение мышью** (как в проводнике):
  - клик — выделить одну клавишу или кнопку мыши, остальное снимается;
  - Ctrl+клик — добавить или убрать одну клавишу;
  - Shift+клик — выделить диапазон прямоугольником в сетке клавиатуры от последней кликнутой клавиши до текущей (см. «Сетка» ниже): выделяются клавиши, которые задевают прямоугольник, в том числе Fn, регулятор и другие непередаваемые клавиши (Q → D даёт Q W E A S D);
  - рамка — зажать мышь на пустом месте или на клавише и протянуть, выделяются клавиши и кнопки мыши под рамкой: в 3D — клавиши, верхнюю грань которых задевает рамка (чтобы не цеплять клавиши «позади»), в 2D — по всей клавише; с Ctrl рамка добавляет к выделению. Клик без протягивания выделяет клавишу — по любой её видимой части, включая боковые грани и самый край;
  - клик по пустому месту или Esc — снять выделение.
- **Кнопки мыши** выделяются так же, как клавиши: кликом, Ctrl+кликом, Shift+кликом, рамкой и Shift+стрелками. Для диапазона и стрелок мышь стоит справа от клавиатуры: Shift+клик от Q до левой кнопки мыши захватывает клавиши и кнопки между ними, стрелка вправо с правого края клавиатуры переходит на мышь. Мышь — продолжение рядов клавиатуры справа: ЛКМ, колесо и ПКМ стоят в ряду F12, Mouse 5 — в ряду Delete, Mouse 4 — в ряду PgUp. Внутри мыши стрелки ходят по положению кнопок: ЛКМ ↔ нажатие колеса ↔ ПКМ (с Shift колесо выделяется целиком), ЛКМ ↓ Mouse 5 ↓ Mouse 4, Mouse 5 → ЛКМ.
- **Сетка для стрелок и диапазонов:** у каждой клавиши есть ряд и столбец (широкая — несколько столбцов), как в таблице. Сетка — часть раскладки (`navGrid` в `src/layouts/aula-f75.ts`). В буквенно-цифровом блоке столбец — пальцевая зона слепой печати: 1 и 2 — левый мизинец, 3 — безымянный, 4 — средний, 5 и 6 — левый указательный, 7 — правый указательный, 8 — средний, 9 — безымянный, 0, - и = — мизинец; ниже — по диагонали пальца (С → В → У → 4). Остальные клавиши — по положению; справа сетку продолжают регулятор и мышь.
  - ← и → — следующая клавиша ряда, пустые места пропускаются; стрелки останавливаются и на Fn, регуляторе и других непередаваемых клавишах (F12 → регулятор → ЛКМ).
  - ↑ и ↓ — клавиша соседнего ряда в том же столбце; столбец запоминается: с пробела стрелка вверх возвращает туда, откуда пришли. В пустом месте — ближайшая клавиша ряда.
  - Shift+стрелки и Shift+клик выделяют прямоугольник сетки, поэтому столбец под F12 (Backspace, «\», Enter, ↑, ↓) не теряет клавиши разной ширины.
  - Shift+← и Shift+→ расширяют выделение на один столбец сетки за нажатие, а не на клавишу: зона из двух столбцов (правый указательный) добавляется в два нажатия, на широкой клавише курсор стоит, пока не дойдёт до её края (2 Q A Z → ← добавляет 1, Tab, Caps, Shift, следующее ← — только Ё, ↓ — Ctrl). Столбцы, которые ничего не меняют (внутри пробела), проходятся за одно нажатие. Без Shift стрелки переходят на соседнюю клавишу целиком.
- **Отображение:** выделенные клавиши — толстая обводка акцентного цвета.
- **Панель справа:**
  - одна клавиша — заголовок с клавишей и её действия строками с кнопками клавиш (FR-12), контекст, категория, тип нажатия, параметр, слот; конфликты отмечены красным;
  - несколько клавиш — действия всех выделенных клавиш по группам, плюс кнопка «Создать группу» (FR-29);
  - ничего не выделено — список действий игры с поиском (FR-16) и вкладка «Без клавиши» (FR-17);
  - у одной выделенной клавиши — кнопка «Назначить действие»: список действий с поиском. Выбор открывает окно привязки для первого свободного слота с этой клавишей и модификаторами текущего слоя. Действие, у которого заняты все слоты, выбрать нельзя: оно отмечено «Все клавиши заняты», в подсказке — «У действия уже назначено клавиш: 1 из 1…» (TC-02);
  - на непередаваемой клавише — сообщение, что на неё нельзя назначить действие, без кнопки.
- **Раскладка как в меню игры:** разделы по категориям с пояснением, подразделами и двумя колонками, когда панель шире ~620 px; уже — одна колонка (сначала левая, потом правая). Колонки и подразделы задаются в заготовках (поля `column`, `subgroup`), у своих игр раздел делится пополам. Категория с `display: slots` («Способности и предметы» в Dota 2) показывается ячейками: вкладки по контекстам действий (Герой, Курьер, Существа), ячейки способностей с клавишей в углу и короткой подписью, ячейки предметов (действия с подразделом, общие для вкладок: 3×2 основных и за чертой — остальные) и кружки режима каста для каждой группы — вариант ставится всем её биндам.
- **Вкладки панели:** выделение клавиши переключает на «Действия» со вкладок «Без клавиши», «Настройки», «Заметки»; с вкладки «Группы» не уводит — там добавляют выделенные клавиши в группу.
- **Ширина панели** 320–900 px, меняется перетаскиванием границы и стрелками с фокусом на границе. Запоминается в браузере (`localStorage`), в `data.json` не попадает.
- **Критерии приёмки:**
  - [ ] Shift+клик от Q до D выделяет ровно Q W E A S D.
  - [ ] Ctrl+клик по выделенной клавише снимает с неё выделение, не трогая остальные.

#### FR-14. Слои модификаторов

- **Описание:** переключатель слоёв над клавиатурой: «Без модификатора», «Ctrl», «Shift», «Alt» и сочетания, которые используются в профиле. На кнопке слоя — число биндов.
- **Переключение:** кнопками переключателя или нажатием комбинации на настоящей клавиатуре в режиме «Проверка нажатий». Клавиша без модификаторов возвращает основной слой; модификатор, нажатый и отпущенный один, выделяет себя в основном слое. Клик по экранным Ctrl, Shift, Alt слой не переключает: он выделяет саму клавишу, потому что на неё тоже бывают бинды.
- **В слое** с модификатором подсвечены клавиши с биндами этого модификатора, остальные приглушены. В основном слое свободные клавиши просто нейтральные, без приглушения.
- **Модификаторы** не различаются на левые и правые. Сами клавиши Shift, Ctrl, Alt можно назначать как обычные (например, Shift — «Бег»).

#### FR-15. Конфликты и нарушения правил

- **Конфликт** — два бинда в одном профиле с одинаковыми клавишей, модификаторами и типом нажатия, если их контексты совпадают или один из них «Везде».
- **Не конфликт:** одна клавиша в контекстах «Пешком» и «В транспорте»; одна клавиша с разным типом нажатия.
- **Нарушение правил** — у действия больше клавиш, чем разрешено в игре (например, после смены правила с 2 на 1). Бинды не удаляются, а подсвечиваются.
- **Отображение:** красная обводка клавиши, значок в слое, счётчик в шапке. Клик по счётчику показывает список всех конфликтов и нарушений с переходом к клавише.
- **Пересчёт** при каждом изменении, не дольше 50 мс.

#### FR-16. Поиск действия

- **Описание:** поле поиска над списком действий, по русскому и английскому названию, без учёта регистра.
- **Результат:** список совпадений; наведение или клик по действию подсвечивает его клавиши, остальные приглушаются (и в основном слое), слой переключается при необходимости. Наведение подсвечивает, пока указатель над строкой; клик закрепляет подсветку, повторный клик или Esc снимают.

#### FR-17. Неназначенные действия

- **Описание:** вкладка «Без клавиши» со списком действий игры без бинда в текущем профиле, с кнопкой «Назначить клавишу» у каждого.

#### FR-18. Значения настроек с ползунками

- **Где:** вкладка «Настройки» в панели профиля.
- **Отображение:** группы как в шаблоне. Ползунок с полем для точного значения рядом, переключатели, списки, текст. У значения, отличного от значения по умолчанию, есть кнопка сброса. Место под кнопку сброса есть всегда, строки не сдвигаются; длинные названия переносятся. Кнопка «Сбросить все настройки» с подтверждением возвращает все значения профиля к значениям по умолчанию, бинды не меняются.
- **Валидация:** число вне диапазона в поле приводится к ближайшей границе с подсказкой «Допустимо от … до …». Значение округляется до шага. Не число — поле возвращает прежнее значение с подсказкой «Введите число».
- **Хранение:** заданное значение хранится, даже если равно значению по умолчанию, — смена умолчания в шаблоне его не тронет. Сброс удаляет значение: профиль снова следует за шаблоном.
- **Критерии приёмки:**
  - [ ] Ползунок и поле синхронизированы в обе стороны.
  - [ ] Значения сохраняются отдельно для каждого профиля.

#### FR-19. Папка данных и автосохранение

- **Первый запуск:** выбор папки (сценарий 1). Ссылка на папку хранится в IndexedDB, при следующих запусках выбор не нужен.
- **Структура папки:** `data.json` — все данные; `icons/` — иконки игр; `backups/` — резервные копии.
- **Автосохранение:** через 1 секунду после последнего изменения. В шапке статус: «Сохранено», «Сохранение…», «Ошибка сохранения».
- **Разрешение:** если браузер снова спрашивает доступ, показывается экран «Разрешить доступ к папке» с кнопкой. Совет выбрать «Разрешать при каждом посещении».
- **Смена папки** — в окне «Настройки» (меню в шапке), с переносом данных или открытием существующих. Если в новой папке уже есть `data.json` — выбор «Открыть данные этой папки» или «Перенести текущие (заменить)»; пустая папка получает текущие данные и иконки. В режиме Firefox раздела нет.

#### FR-20. Резервные копии

- **Когда:** при каждом запуске, перед записью первого изменения — копия `data.json` в `backups/` с датой и временем в имени.
- **Хранится** 5 последних, старые удаляются.
- **Восстановление:** список копий в окне «Настройки», кнопка «Восстановить» с подтверждением; текущее состояние перед этим тоже сохраняется в копию. Работает и в режиме Firefox: копии там — записи IndexedDB. Восстановление очищает историю отмены (FR-24).

#### FR-21. Импорт и экспорт

- **Где:** меню в шапке — «Импорт…» и «Экспорт» (всё, текущая игра, текущий профиль); кнопка «Экспортировать» в напоминании режима Firefox (FR-23).
- **Экспорт:** всё, одна игра или один профиль. Файл `*.hotkeymap.json` скачивается как обычная загрузка (одинаково в Chrome и Firefox), имя — по названию и дате: `dota-2-2026-10-26.hotkeymap.json`, `hotkeymap-2026-10-26.hotkeymap.json`. Иконки встроены в файл (раздел 9.4). Экспорт профиля — его игра со всеми справочниками, но только с этим профилем: без справочников бинды ссылались бы в никуда. Дата `lastExportAt` обновляется только экспортом всего.
- **Импорт:**
  1. Выбрать файл или перетащить его в любое место окна. Поле иконки в редакторе игры перетаскивание не отдаёт.
  2. Проверить схему и версию (через миграции). Ошибки показываются списком с понятным местом («Игра «Dota 2» → действие 12: неизвестный контекст»), первые 20 и «и ещё N»; импорт не выполняется. Файл новее приложения — отдельное сообщение.
  3. Показать предпросмотр: игры из файла с отметкой «новая игра» или «совпадает», число новых и совпадающих действий, профили с отметкой «новый» или «совпадает».
  4. При совпадении игры или профиля предложить: объединить (по умолчанию), создать копию или заменить.
  5. После импорта — итог: что добавлено и сколько биндов пропущено.
- **Совпадение:** сначала по id, потом по названию без учёта регистра. Так заготовка «Dota 2» находит игру «Dota 2», созданную с другими id. Внутри игры так же сопоставляются контексты, категории, действия (название — в пределах контекста), настройки шаблона, варианты параметра, профили.
- **Стратегии для игры:**
  - **Объединить** — существующее не меняется, недостающее добавляется: контексты, категории, действия, настройки шаблона, варианты параметра. У совпавших элементов остаются ваши значения, ссылки из файла перенаправляются на них. Профили обрабатываются по своим стратегиям.
  - **Создать копию** — все id новые, занятое название получает номер: «Dota 2 (2)».
  - **Заменить** — игра из файла встаёт на место существующей целиком, на ту же позицию в списке.
- **Стратегии для профиля** (внутри объединяемой игры):
  - **Объединить** — бинды из файла добавляются в свободные слоты; если такой бинд уже есть или нужный слот занят — бинд пропускается и попадает в итог. Значения настроек: ваши остаются, недостающие добавляются. Группы клавиш: новые добавляются, клавиши, уже входящие в группу, пропускаются. Заметки остаются ваши.
  - **Создать копию** — новый профиль, занятое название получает номер: «Основной (2)».
  - **Заменить** — профиль из файла встаёт на место существующего.
- **Настройки приложения** из файла экспорта всего применяются, только если в приложении ещё нет игр.
- **Отмена:** весь импорт — один шаг отмены (FR-24).
- **Критерии приёмки:**
  - [ ] Экспорт всего и импорт в чистое приложение восстанавливают данные полностью.
  - [ ] Повреждённый файл не меняет текущие данные.

#### FR-22. Заготовки Dota 2 и PUBG

- **Описание:** готовые файлы импорта в репозитории с действиями, контекстами, категориями, параметром бинда и шаблоном настроек по актуальному меню игр. Названия на русском, как в русском клиенте, с английским оригиналом. Биндов в заготовках нет, только справочники. Исключение — профиль «Тестовый» в заготовке Dota 2 с биндами и настройками автора (профиль «Основной» пустой). Контексты Dota 2: «Везде» — только служебные действия (пауза, консоль, чат, таблица счёта, карта на весь экран), «Общий» — основной контекст для большинства действий, «Герой», «Курьер», «Существа», «Выбор таланта», «Выбор нейтрального предмета». В «Тестовом» конфликтов нет.
- **Где:** предложение при первом запуске, кнопка «Из заготовок» в пустом состоянии и в выборе игры, ссылка «Добавить из заготовок» при создании игры. Заготовка добавляется общим импортом (FR-21): с предпросмотром и стратегиями, поэтому повторный импорт обновлённой заготовки в режиме «Объединить» добавляет только новые действия и настройки. Предложение при первом запуске — сразу после выбора папки, если в ней ещё нет игр (сценарий 1, шаг 4).
- **Правила:** Dota 2 — 1 клавиша на действие, параметр «Режим каста». PUBG — 2 клавиши на действие, контексты для разных режимов (пешком, транспорт, парашют и т. п.).

#### FR-23. Запасной режим Firefox

- **Описание:** если File System Access API недоступен, данные хранятся в IndexedDB. Вверху постоянная плашка: «Данные хранятся в браузере. Для хранения в папке откройте в Chrome или Edge».
- **Напоминание** сделать экспорт, если последнего экспорта не было 7 дней. Кнопки «Экспортировать» (сразу скачивает экспорт всего) и «Позже» (скрывает до конца сессии).

#### FR-24. Отмена и повтор

- **Описание:** кнопки «Отменить» и «Повторить» в шапке рядом с выбором игры и профиля, история 50 шагов в пределах сессии.
- **Горячие клавиши:** Ctrl+Z — отменить, Ctrl+Shift+Z — повторить. Работают только в режиме «Навигация» (FR-03) и не в полях ввода: в режиме «Проверка нажатий» эти нажатия выделяют клавиши, в полях работает отмена браузера.
- **В историю попадает** всё содержимое игр: справочники, профили, бинды, значения настроек, группы, заметки, импорт (одним шагом). Перетаскивание ползунка — один шаг.
- **В историю не попадают** настройки приложения (`appSettings`): тема, вид 2D/3D, расцветка, язык подписей и «Авто», режим ввода, режим окраски, подписи на клавишах, показ клавиатуры и мыши, последняя игра и профиль, `lastExportAt`. Выделение и ширина панели — тоже нет.
- **История общая** для всех игр и переживает их переключение. Если отменяемое или повторяемое изменение было в другой игре или профиле, приложение переключается туда. Если отмена убрала текущую игру или профиль — открывается соседний.
- **Очистка:** загрузка данных при запуске, смена папки и восстановление из копии очищают историю.
- **Всплывающее сообщение** с кнопкой «Отменить» — после удаления игры, профиля, действия, контекста, категории, группы клавиш и настройки шаблона. После снятия бинда не показывается: это частое действие.

#### FR-25. Темы

- **Варианты:** системная (по умолчанию), светлая, тёмная. Переключатель в шапке — кнопка-иконка с меню, выбор запоминается в `appSettings.theme`. Тёмная тема — класс `.dark` на `<html>`; системная следует `prefers-color-scheme` и меняется вместе с системой без перезагрузки.

#### FR-26. Подписи действий на клавишах

- **Описание:** переключатель «Подписи на клавишах». Включено — короткая подпись первого действия на клавише крупным шрифтом и мелкое «+N», если действий больше. Подпись — поле действия «Подпись на клавише» (до 5 символов, «СП1», «УЛЬТ») или сокращение названия: «Способность 1» → «СП1», несколько слов — первые буквы («Изучить левый талант» → «ИЛТ»), одно слово — 3 буквы. Полное название — в подсказке и у выносок мыши. Выключено — только подсветка цветом. По умолчанию включено.
- **Вид:** с подписью действия название клавиши уменьшается и уходит в левый верхний угол, подпись — снизу. Кегль уменьшается под ширину клавиши. У ЛКМ и ПКМ подпись в середине кнопки, у остальных входов мыши — полное название под выноской.
- **Где:** переключатель над клавиатурой, рядом со слоями и режимом окраски.

#### FR-27. Защита от двух вкладок

- **Описание:** вторая открытая вкладка определяет первую (BroadcastChannel) и работает только для просмотра с плашкой «Приложение уже открыто в другой вкладке».
- **Проверка** — при запуске, до чтения данных и записи резервной копии. Вкладка для просмотра ничего не записывает, правки в ней не применяются.

#### FR-28. Обновление PWA

- **Описание:** при выходе новой версии — плашка «Доступна новая версия» с кнопкой «Обновить». Новая версия не включается сама: только по кнопке (`vite-plugin-pwa`, режим `prompt`).

#### FR-29. Группы клавиш

- **Описание:** пользователь объединяет клавиши в именованные группы с цветом, например «Под левой рукой» или «Способности». Группы относятся к профилю.
- **Создание:** выделить клавиши (FR-13) → «Создать группу» в панели → название (1–40 символов) и цвет из палитры или HEX.
- **Правила:** клавиша входит не больше чем в одну группу. Если выделенная клавиша уже в другой группе, приложение спрашивает, перенести ли её. Fn и регулятор в группы не входят.
- **Копирование в другой профиль:** если там клавиши уже в группах — вопрос о переносе в копию; занятое название получает номер «(2)».
- **Управление:** список групп во вкладке «Группы» панели: переименовать, сменить цвет, добавить или убрать выделенные клавиши, удалить, скопировать в другой профиль.
- **Критерии приёмки:**
  - [ ] Клавишу нельзя добавить в две группы одновременно.
  - [ ] Группа копируется в другой профиль этой игры.

#### FR-30. Режим окраски

- **Описание:** переключатель над клавиатурой рядом со слоями: «По категориям» или «По группам». Цвета не смешиваются.
- **По категориям:** клавиша заливается цветом категории первого действия, при нескольких категориях — полосками цветов.
- **По группам:** клавиша заливается цветом своей группы, клавиши вне групп нейтральные. Категории действий видны цветной меткой в панели справа.
- **Выделение и конфликты** в обоих режимах показываются обводкой: акцентной и красной со значком.
- **По умолчанию:** «По категориям», выбор запоминается.

### 7.3. Матрица прав доступа

## 8. Интерфейс и UX

### 8.1. Карта экранов и навигация

Приложение одноэкранное: всё основное на главном экране, редактирование — в боковых панелях и диалогах.

- **Первый запуск** → выбор папки → предложение заготовок → **Главный экран**.
- **Главный экран:**
  - шапка → **Редактор игры**, **Импорт и экспорт**, **Настройки приложения**;
  - панель справа → вкладки **Действия**, **Без клавиши**, Группы, **Настройки профиля**, **Заметки**;
  - выбор клавиши → панель действий клавиши → кнопки клавиш в строках действий и «Назначить действие»;
  - счётчик конфликтов → **Список конфликтов**.

### 8.2. Описание экранов

| Экран | Назначение | Основные элементы | Действия |
| --- | --- | --- | --- |

**Пустые состояния:**

- Нет игр: панель слева от клавиатуры — «Добавьте первую игру» и кнопки «Создать игру» и «Из заготовок».
- Нет действий: «В игре пока нет действий» и кнопка «Добавить действие».
- Клавиша без биндов: «На клавише ничего нет» и кнопка «Назначить действие».

### 8.3. Визуальный стиль

- **Общий стиль:** минималистичный, «игровой», без лишних украшений. Клавиатура — главный визуальный объект.
- **Цвета:** нейтральные фон и корпус клавиатуры, две расцветки клавиш — «Стандартная» и «Чёрная» (FR-01), акцентный цвет для выбора, красный для конфликтов, цвета категорий задаёт пользователь. Все цвета — CSS-переменные для тем.
- **Шрифты:** Inter для интерфейса; шрифт и размеры подписей на клавишах задаёт тема устройств (`legend` в `device-theme.ts`).
- **Темы:** системная, светлая, тёмная.
- **Иконки:** lucide-react.
- **3D:** перспектива и наклон из темы устройств (клавиатура 32°, мышь 16° с более сильной перспективой), мягкие тени, у клавиш видны верхняя, передняя и внутренняя боковая грани.

### 8.4. Адаптивность и размеры окна

- Минимальный размер окна 1280×720, меньше — горизонтальная прокрутка.
- Клавиатура и мышь масштабируются по ширине центральной области.
- Панель справа меняет ширину в пределах 320–900 px.
- Окно PWA запоминает размер и положение (средствами браузера).

### 8.5. Управление и доступность

- **Мышь:** клик, Ctrl+клик, Shift+клик, рамка — как в проводнике, для клавиш и кнопок мыши (FR-13).
- **Клавиатура в режиме «Проверка нажатий»:** нажатия выделяют нажатые клавиши (FR-03); Esc снимает выделение или закрывает диалог.
- **Клавиатура в режиме «Навигация»:** стрелки, Shift+стрелки, Ctrl+A, Ctrl+Z, Ctrl+Shift+Z, Esc.
- **Действия приложения** (экспорт, импорт, тема и т. п.) — кнопками, без горячих клавиш, чтобы не мешать проверке биндов. Исключение — отмена и повтор в режиме «Навигация» (FR-24).
- **Доступность:** диалоги и формы полностью управляются с клавиатуры, контраст текста не ниже 4.5:1, категория показывается не только цветом, но и названием в панели.

### 8.6. Тексты и язык интерфейса

- **Язык интерфейса:** русский. Все строки в одном файле `src/i18n/ru.ts`, чтобы позже добавить другие языки.
- **Подписи клавиш:** английские и русские, активный язык ярче (FR-04).
- **Тон:** на «вы», коротко и по делу.
- **Форматы:** дата ДД.ММ.ГГГГ, время ЧЧ:ММ, десятичный разделитель — запятая.

## 9. Данные и хранение

### 9.1. Сущности и модель данных

Все идентификаторы — UUID (`crypto.randomUUID()`). У сущностей верхнего уровня есть поля `createdAt` и `updatedAt` в формате ISO 8601.

**AppData** — корень файла `data.json`

| Поле | Тип | Описание |
| --- | --- | --- |
| schemaVersion | Integer | Версия схемы данных, начиная с 1 |
| games | Game\[\] | Игры |
| appSettings | Object | `theme` (system, light, dark), `labelLang` (enru, en, ru), `autoLang`, `view` (3d, 2d), `showLabels`, `colorMode` (category, group), `inputMode` (check, nav), `showKeyboard`, `showMouse`, `keyboardColor` (standard, black), `lastGameId?`, `lastProfileId?`, `lastExportAt?` — дата последнего экспорта для напоминания FR-23. У каждого поля есть значение по умолчанию: недостающие поля при загрузке заполняются |

**Game** — игра

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| id, name | UUID, String | Да | Идентификатор и название |
| icon | String | Нет | Имя файла в `icons/` |
| steamAppId | Integer | Нет | AppID в Steam |
| rules | Object | Да | `maxKeysPerAction`: 1 или 2; `allowedModifiers`: набор из ctrl, shift, alt; `blockedKeys`: коды клавиш, которые не передаются в игру (по умолчанию `Fn`, `Knob` — Fn и регулятор; `MetaLeft` — Win — добавляется для игр, где она не назначается) |
| contexts | Context\[\] | Да | Контексты, всегда содержит системный «Везде» |
| categories | Category\[\] | Да | Категории |
| actions | Action\[\] | Да | Действия |
| bindParam | BindParam | Нет | Параметр бинда |
| settingsTemplate | SettingDef\[\] | Да | Шаблон настроек |
| profiles | Profile\[\] | Да | Профили, минимум один |

**Вложенные сущности**

| Сущность | Поля |
| --- | --- |
| Context | id, name, isGlobal (true только у «Везде»), order |
| Category | id, name, color (HEX), note? (пояснение раздела), display? (list, slots) |
| Action | id, name, nameEn?, contextId, categoryId?, description?, short? (подпись на клавише, до 5 символов), column? (1, 2), subgroup?, order |
| BindParam | name, options: { id, name }\[\] |
| SettingDef | id, group, name, type (slider, toggle, select, text, info), unit?, min?, max?, step?, options?, display? (list, radio — у select), text? и height? (у info), defaultValue (нет у info), column?, subgroup?, order |
| Profile | id, name, notes, bindings: Binding\[\], settingValues: { settingId: value }, keyGroups: KeyGroup\[\] |
| Binding | id, actionId, input: { device (keyboard, mouse), code, modifiers }, pressType (press, hold, toggle, double, long), paramOptionId?, slot (1 или 2) |
| KeyGroup | id, name, color (HEX), inputs: коды входов\[\]; один вход — не больше чем в одной группе профиля |

Коды входов: для клавиатуры — значения `KeyboardEvent.code` (`KeyQ`, `Digit1`, `ShiftLeft`); для мыши — `MouseLeft`, `MouseRight`, `MouseMiddle`, `WheelUp`, `WheelDown`, `Mouse4`, `Mouse5`.

### 9.2. Связи между сущностями

- Игра 1 — N контексты, категории, действия, настройки шаблона, профили.
- Профиль 1 — N бинды. Бинд ссылается на действие той же игры.
- Действие N — 1 контекст, N — 0..1 категория.
- **Удаление:** игры — со всеми данными; действия — с его биндами во всех профилях; категории — снимается с действий; контекста — только с переносом действий; настройки шаблона — значения удаляются из профилей. Каждое удаление с подтверждением и числом затронутых записей.

### 9.3. Хранение

| Параметр | Значение |
| --- | --- |
| Где хранятся данные | Папка на диске, выбранная пользователем (File System Access API). В режиме Firefox — IndexedDB |
| Состав папки | `data.json`, `icons/`, `backups/` |
| Ожидаемый объём | До 2 МБ `data.json`, иконки до 50 КБ каждая |
| Запись | Через 1 с после последнего изменения, целиком файл |
| Резервные копии | При каждом запуске, 5 последних (FR-20) |
| Срок хранения | Бессрочно |
| Миграции схемы | При загрузке: если `schemaVersion` меньше текущей — последовательные функции миграции, перед миграцией — резервная копия. Если больше — сообщение «Данные созданы более новой версией приложения, обновите страницу» |
| Имена копий | `backups/data-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.json` по местному времени. Повреждённый `data.json` перед восстановлением откладывается в `backups/damaged-….json`: такие файлы не считаются копиями, не вытесняют их и не показываются в списке |
| Режим Firefox | Те же данные, копии и иконки — записями в IndexedDB. Отсчёт для напоминания об экспорте — от `lastExportAt`, а если экспорта не было — от первой записи данных в браузер |

### 9.4. Импорт и экспорт

| Направление | Формат | Что переносится | Примечания |
| --- | --- | --- | --- |
| Экспорт | `*.hotkeymap.json` | Всё, одна игра или один профиль | UTF-8, поля `schemaVersion`, `scope` (all, game, profile), `exportedAt`, `games`, `appSettings?` (только у all), `preset?` (у заготовок), `icons?` — объект «имя файла → `data:image/png;base64,…`» |
| Импорт | `*.hotkeymap.json` | То же | Проверка схемой Zod после миграций, предпросмотр, стратегии: объединить, копия, заменить (FR-21); лимит 20 МБ. Иконка записывается в `icons/` под новым именем и не затирает существующие |

Файл экспорта и `data.json` используют одну версию схемы и одни миграции. Файл с `scope: 'profile'` — одна игра с одним профилем.

Совместимость с файлами конфигов игр — этап 2.

### 9.5. Справочники и начальные данные

- **В каждой новой игре:** контекст «Везде», профиль «Основной».
- **Раскладка клавиатуры:** AULA F75 (приложение А), раскладка мыши с 7 входами.
- **Заготовки:** `src/presets/dota2.json` и `src/presets/pubg.json` — действия, контексты, категории с цветами, параметр бинда, шаблон настроек. Составляются по актуальному меню игр при разработке.
- **Палитра категорий:** 12 предустановленных цветов, различимых в обеих темах.
- **Пример структуры данных** — приложение Б.

## 13. Ошибки и граничные случаи

### 13.1. Обработка ошибок

| Ситуация | Что видит пользователь | Что делает система |
| --- | --- | --- |
| Неверные данные в форме | Поле подсвечено, под ним причина; кнопка «Сохранить» неактивна | Не сохраняет |
| Браузер не поддерживает доступ к файлам | Плашка про запасной режим (FR-23) | Переключается на IndexedDB |
| Нет разрешения на папку | Экран «Разрешить доступ к папке» с кнопкой | Ждёт разрешения, данные не теряются: изменения держатся в памяти |
| Папка удалена или перемещена | «Папка данных не найдена» и кнопки «Выбрать папку» и «Создать новую» | Предлагает выбрать заново |

### 13.2. Граничные случаи

- Комбинация, которую перехватывает браузер или Windows (Ctrl+W, Alt+F4) → не ловится нажатием, назначается кликом.
- Fn и регулятор (и другие непередаваемые клавиши игры, например Win) → не назначаются; пока зажата кнопка мыши, видны вспышка отказа и подсказка «Эта клавиша не передаётся в <игра>» (FR-01). В выделение попадают рамкой, Shift+кликом, Ctrl+кликом и стрелками — красными, без подсказки; обычный клик выделение не меняет.
- Пустые места сетки (между Esc и F1, между F8 и F9, зазор перед стрелками) → стрелка ↑ или ↓ выбирает ближайшую клавишу ряда; пробел занимает шесть столбцов и запоминает столбец, с которого на него пришли.
- Включена русская раскладка ввода → клавиши определяются по физическому коду, бинды работают так же.
- Действие удаляется, а у него бинды в нескольких профилях → подтверждение с числом биндов.
- Правило «клавиш на действие» меняется с 2 на 1 → лишние бинды не удаляются, а отмечаются как нарушение.
- Удаляется модификатор из допустимых → бинды с ним отмечаются как нарушение.
- Удаление последнего профиля → запрещено.
- Двойной клик по «Сохранить» → создаётся одна запись, кнопка блокируется на время сохранения.
- Длинные названия → обрезаются многоточием на клавише и в списках, полностью видны в подсказке.
- На клавише 10 и больше действий → панель прокручивается, на клавише «+N».
- В поле ползунка вводится значение вне диапазона или не число → приводится к границе или к прежнему значению с подсказкой.
- Импорт игры с таким же id или названием → диалог стратегии (объединить, копия, заменить).
- Вторая вкладка → режим только для просмотра (FR-27).
- Окно меньше 1280×720 → появляется прокрутка, интерфейс не ломается.
- Firefox, боковые кнопки мыши в режиме проверки → вход выделяется, но браузер может уйти «Назад» или «Вперёд»: Firefox не даёт это отменить. Остальное в Firefox работает как в Chrome (NFR-07).

- **Где:** консоль браузера. Внешние сервисы мониторинга не используются.
- **Срок хранения:** не хранится.

## 15. Сборка, развёртывание и обновления

### 15.1. Окружения

| Окружение | Назначение | Где работает | Данные |
| --- | --- | --- | --- |
| Разработка | Написание и отладка кода | `localhost:5173`, команда `npm run dev` | Отдельная тестовая папка данных |
| Продакшн | Ежедневное использование | GitHub Pages, установлено как PWA | Реальная папка данных |

Локальный адрес и GitHub Pages — разные сайты, у каждого своё разрешение на папку. Для разработки выбирается отдельная папка, чтобы не задеть реальные данные.

### 15.2. Сборка и выпуск

- **Сборка:** `npm run build`, результат — статические файлы в `dist/`.
- **CI/CD (GitHub Actions):**
  - на каждый push и pull request — линтер, проверка типов, тесты;
  - на push в `main` — дополнительно сборка и публикация на GitHub Pages.
- **Версии:** SemVer, тег `v1.0.0` — MVP. Номер версии виден в настройках приложения.

### 15.3. Установка и первый запуск

1. Открыть адрес приложения на GitHub Pages в Chrome или Edge.
2. Нажать значок установки в адресной строке — появится ярлык на рабочем столе.
3. Выбрать папку данных и разрешить доступ «при каждом посещении».
4. Загрузить заготовки Dota 2 и PUBG или начать с нуля.

### 15.4. Обновления

- **Доставка:** автоматически после публикации, плашка «Доступна новая версия» (FR-28).
- **Совместимость данных:** миграции схемы при загрузке, резервная копия перед миграцией.
- **Откат:** `git revert` проблемного коммита и повторная публикация; данные восстанавливаются из резервной копии.

### 15.5. Поддержка

- Ошибки и идеи — в Issues репозитория на GitHub.
- Мониторинг не нужен: приложение работает целиком в браузере.
