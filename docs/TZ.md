## 1. Общие сведения

### 1.1. Название и краткое описание

**Название:** Hotkey Map

**Описание:** веб-приложение, которое показывает игровые бинды на объёмной экранной копии клавиатуры и мыши пользователя и хранит их по играм и профилям игроков в папке на компьютере.

### 1.2. Предпосылки и проблема

- Бинды в играх приходится вспоминать или искать в меню настроек, где не видно, какие клавиши заняты и где конфликты.
- За одним ПК могут играть разные люди, у каждого свои привычные настройки.
- Бинды и настройки (чувствительность, FOV и т. п.) хранятся локально и теряются при смене ПК или переустановке системы.
- Готового наглядного инструмента, который показывает бинды на копии своей клавиатуры, нет.

### 1.3. Назначение

**Этап 1** — личное использование на одном ПК с Windows. Приложение открыто в отдельном окне или на втором мониторе, им пользуются перед игрой или во время паузы. Внутри одной игры можно вести профили нескольких людей. Приложение бесплатное и работает без сервера.

**Этап 2** — многопользовательский сервис для хранения и переноса биндов и конфигов игр между компьютерами (раздел 4.5).

### 1.4. Термины и сокращения

| Термин | Определение |
| --- | --- |
| Игра | Группа, внутри которой хранятся действия, контексты, категории, шаблон настроек и профили |
| Действие | Игровая команда, которую можно назначить на клавишу, например «Прыжок». Вводится вручную по меню игры |
| Контекст | Режим игры, в котором действует команда: «Пешком», «В транспорте». Особый контекст «Везде» действует во всех режимах |
| Категория | Группа действий с названием и цветом («Движение», «Бой»), по ней подкрашиваются клавиши |
| Профиль | Вариант настроек одного игрока в игре: бинды и значения настроек |
| Бинд | Связь действия с клавишей или кнопкой мыши в профиле, с учётом модификаторов и типа нажатия |
| Модификатор | Клавиша Ctrl, Shift или Alt в составе комбинации |
| Комбинация | Бинд из модификатора и основной клавиши, например Ctrl+1 |
| Слой | Режим экранной клавиатуры, который показывает бинды с выбранным модификатором |
| Тип нажатия | Как срабатывает бинд: нажатие, удержание, переключение, двойное нажатие, долгое нажатие |
| Параметр бинда | Дополнительное свойство бинда со списком значений, заданным для игры. Пример: режим каста в Dota 2 |
| Конфликт | Ситуация, когда одна клавиша с теми же модификаторами и типом нажатия назначена на разные действия в пересекающихся контекстах |
| Шаблон настроек | Список настроек игры (чувствительность, FOV) с типом и диапазоном, общий для всех профилей игры |
| Раскладка клавиатуры | Описание физического расположения клавиш конкретной модели. Не путать с языком ввода |
| Язык подписей | Какие символы подсвечены на клавишах: английские или русские |
| Папка данных | Папка на диске, выбранная пользователем, где приложение хранит свои файлы |
| PWA | Веб-приложение, которое устанавливается из браузера как программа: ярлык, своё окно, работа без интернета |
| MVP | Минимальная рабочая версия, версия 1.0 |

### 1.5. Ссылки и источники

- [AULA F75 — страница модели](https://epomaker.com/products/aula-f75-wired): 75% ANSI с регулятором. 80 клавиш, справа от пробела Fn и Ctrl, правого Alt нет.
- [File System Access API — MDN](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API): доступ к папке на диске из браузера.
- Меню настроек управления Dota 2 и PUBG: источник для заготовок действий и шаблонов настроек.

## 2. Цели, задачи и критерии успеха

### 2.1. Цель проекта

За 1–3 дня сделать приложение, в котором бинды любой игры и любого профиля видны на одном экране, на точной копии своей клавиатуры, а все настройки надёжно хранятся в файле на компьютере и переносятся на другой ПК за минуту.

### 2.2. Задачи

1. Отобразить объёмную копию клавиатуры AULA F75 и мыши с двумя боковыми кнопками.
2. Дать вести справочники игры: действия, контексты, категории, параметры бинда и шаблон настроек.
3. Дать вести несколько профилей в игре: бинды и значения настроек.
4. Показывать действия выбранных клавиш, комбинации с модификаторами и конфликты.
5. Хранить данные в папке на диске с автосохранением и резервными копиями, поддержать импорт и экспорт.
6. Заложить основу для этапа 2: отдельный слой хранения, версия схемы данных, раскладки клавиатур как отдельные файлы.

### 2.3. Учебные цели

- Сделать законченный проект на TypeScript и React.
- Освоить разработку с Claude Code от ТЗ до релиза.
- Разобраться с File System Access API, PWA и отрисовкой 3D-вида (перспективная проекция, SVG).
- Настроить CI/CD на GitHub Actions и публикацию на GitHub Pages.

### 3.4. Ключевые сценарии

**Сценарий 1: Первый запуск**

- **Предусловие:** приложение открыто в Chrome или Edge впервые.
- **Шаги:**
  1. Приложение показывает приветствие и кнопку «Выбрать папку для данных».
  2. Пользователь выбирает папку, браузер спрашивает разрешение, пользователь разрешает.
  3. Приложение создаёт в папке `data.json`, `icons/` и `backups/`.
  4. Приложение предлагает загрузить заготовки Dota 2 и PUBG или начать с нуля.
- **Результат:** открыт главный экран с клавиатурой, данные сохраняются в выбранную папку.

**Сценарий 2: Узнать, что на клавише**

- **Предусловие:** есть игра и профиль с биндами.
- **Шаги:**
  1. Пользователь выбирает игру и профиль в шапке.
  2. Нажимает клавишу на настоящей клавиатуре или кликает по экранной.
  3. Клавиша обводится, в панели справа появляются её действия с контекстом, категорией, типом нажатия и параметром.
  4. Ctrl+кликом добавляет ещё две клавиши, панель показывает действия всех трёх по группам.
- **Результат:** пользователь видит все действия выделенных клавиш.

**Сценарий 3: Назначить бинд**

- **Предусловие:** в игре заведены действия.
- **Шаги:**
  1. Пользователь открывает вкладку «Действия» в панели справа: список повторяет меню настроек игры.
  2. Кликает по кнопке клавиши у нужного действия, кнопка переходит в режим «Нажмите клавишу…».
  3. Нажимает клавишу или комбинацию на настоящей клавиатуре либо кликает по экранной.
  4. Приложение проверяет правила игры и конфликты, при конфликте показывает предупреждение под кнопкой.
- **Результат:** бинд сохранён, клавиша подкрашена, данные записаны в файл.

**Сценарий 4: Посмотреть комбинации с Ctrl**

- **Шаги:**
  1. Пользователь выбирает слой Ctrl в переключателе над клавиатурой или нажимает любую комбинацию с Ctrl на настоящей клавиатуре.
  2. Клавиатура показывает бинды вида Ctrl+клавиша, остальные клавиши приглушены.
  3. Кнопка «Без модификатора» возвращает основной слой.
- **Результат:** видны все комбинации с Ctrl.

**Сценарий 5: Перенос на новый ПК**

- **Шаги:**
  1. На старом ПК пользователь нажимает «Экспорт» → «Всё» и получает файл `.hotkeymap.json`.
  2. На новом ПК открывает приложение, выбирает папку и нажимает «Импорт».
  3. Приложение показывает, что будет импортировано, пользователь подтверждает.
- **Результат:** все игры, профили, бинды, настройки и иконки восстановлены.

### 4.5. Планы развития (этап 2)

*Подробно не прорабатывается, записано, чтобы не потерять идеи и учесть их в архитектуре этапа 1.*

- **Многопользовательский сервис.** Регистрация, вход, хранение биндов и настроек в облачной базе данных. Решает проблему потери настроек при смене ПК или переустановке системы.
- **Лимит профилей.** Например, до 5 профилей на игру у одного пользователя.
- **Конфиги игр.** Минимум — просмотр и ручной перенос настроек. Максимум — импорт и экспорт файлов конфигов в формате конкретной игры. Первые кандидаты — Dota 2 и PUBG.
- **Клавиатуры.** Определение подключённой клавиатуры, если это технически возможно, и библиотека раскладок разных моделей и форматов (60%, 75%, TKL, полноразмерные, ANSI и ISO).
- **Прочее.** Сравнение профилей, автообновление, 3D-модель на Three.js, при необходимости — версия для Windows на Tauri (иконки из ярлыков, хранение в SQLite).

## 5. Выбор платформы

**Решение:** одностраничное веб-приложение (SPA), устанавливаемое как PWA, на GitHub Pages. Данные хранятся в папке на диске через File System Access API в Chrome или Edge. В Firefox работает запасной режим с хранением внутри браузера.

Почему так: приложение используется в отдельном окне, а не поверх игры, и реагирует на клавиши только когда активно — для этого не нужна программа для Windows. Веб-стек быстрее всего делается с Claude Code, бесплатно публикуется из публичного репозитория и проще всего развивается в многопользовательский сайт на этапе 2.

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| Браузер, данные внутри браузера (IndexedDB) | Самый простой, работает везде | Данные теряются при очистке браузера | Только как запасной режим для Firefox |
| **Браузер + папка на диске** | Данные в файлах на ПК, без сервера, бесплатно | Только Chrome и Edge, браузер спрашивает разрешение на папку | **Выбран** |
| Браузер + локальный сервер с SQLite | Настоящая база данных | Два процесса, сервер нужно запускать | Отклонён: сложнее без выгоды на этапе 1 |
| Программа для Windows на Tauri | SQLite, иконки из ярлыков, своё окно | Нужен Rust, дольше настройка | Отложен до этапа 2 при необходимости |

### 6.2. Архитектура

**Тип:** клиентское SPA без сервера, слоистая структура.

| Слой | Ответственность | Взаимодействует с |
| --- | --- | --- |
| Интерфейс (React-компоненты) | Клавиатура, мышь, панели, диалоги, редакторы | Хранилище состояния |
| Хранилище состояния (Zustand) | Текущие данные, выбор, слой, история отмены | Интерфейс, логика, адаптер хранения |
| Логика предметной области | Чистые функции: конфликты, правила игры, валидация, миграции схемы, слияние при импорте | Хранилище состояния |
| Адаптер хранения | Единый интерфейс `StorageAdapter`: загрузить, сохранить, бэкап, иконки | Хранилище состояния, файловая система или IndexedDB |

Ключевые решения:

- **Клавиши определяются по физическому коду** (`KeyboardEvent.code`, например `KeyQ`), а не по символу. Поэтому бинды не зависят от языка ввода: Q и Й — одна клавиша.
- **Адаптер хранения — интерфейс** с реализациями `FileSystemStorage` и `IndexedDbStorage`. На этапе 2 добавится `CloudStorage` без переделки интерфейса.
- **Раскладка AULA F75 — файл данных** `src/layouts/aula-f75.ts`. Новая модель клавиатуры — новый файл, без изменения компонентов.
- **У схемы данных есть номер версии** и функции миграции между версиями.

### 7.2. Подробное описание функций

#### FR-01. 3D-клавиатура AULA F75

- **Описание:** в центре экрана — объёмная копия клавиатуры AULA F75 (75% ANSI, 80 клавиш, регулятор справа сверху). Раскладка — в приложении А.
- **Вид:** как на превью `docs/images/device-*.png`. Камера сверху и немного со стороны пользователя: ряд с пробелом ближе и крупнее, ряд F-клавиш уходит вглубь. Клавиша — усечённая пирамида: верхняя грань со скруглёнными углами, передняя и боковые грани-трапеции; верхняя грань сдвинута наружу от центра по перспективе, наклонена по ряду профиля и не выходит за бока клавиши. Задний край бока идёт по касательной к скруглению верхней грани — без просветов и выступов. У корпуса видна толщина, регулятор — цилиндр.
- **Отрисовка 3D:** перспектива считается в JS и рисуется плоско в SVG, без CSS 3D, чтобы вид работал быстро и переключался без задержек. Подписи и обводка выделения наклоняются вместе с верхней гранью одной плоской трансформацией.
- **Тема устройств:** все цвета, размеры, подписи и параметры 3D — в `src/styles/device-theme.ts`, в компонентах и CSS значений нет.
- **Подписи:** на буквах английская слева сверху, русская справа снизу; на цифрах и символах — верхний символ, основной и русский символ; на модификаторах — значок и слово.
- **Состояния клавиши:** свободна; занята (цвет по режиму окраски, FR-30); выделена (только толстая обводка акцентного цвета); конфликт (красная обводка и значок); приглушена (в чужом слое или при поиске); отказ — у неназначаемой клавиши, пока на ней зажата кнопка мыши (красная рамка и диагональная штриховка, не путается с выделением и цветами групп).
- **Анимация:** при нажатии клавиша проседает, длительность 80–120 мс — и от настоящей клавиатуры, и при клике мышью по клавише (пока зажата кнопка). При выделении рамкой клавиши не проседают.
- **Регулятор, Fn и Win:** отображаются, но назначить на них нельзя: игры и браузер не видят регулятор и Fn, а Win забирает Windows. Пока зажата левая кнопка мыши на такой клавише, видны красная рамка, диагональная штриховка и подсказка; при отпускании они пропадают. Подсказка у клавиш нижнего ряда — под клавишей, у остальных клавиш и регулятора — над ней, на одинаковом расстоянии.
- **Текст подсказки** зависит от выбранной игры: «Эта клавиша не передаётся в Dota 2». У каждой игры свой набор непередаваемых клавиш (поле «Непередаваемые клавиши», FR-05). Пока игр нет, текст общий: «Эта клавиша не передаётся в игры».
- **Переключатель 2D / 3D** в настройках приложения.
- **Масштаб:** клавиатура вписывается в ширину свободной области, пропорции сохраняются. Место под клавиатуру и мышь одинаковое в 2D и 3D, поэтому при переключении вида мышь не сдвигается.
- **Критерии приёмки:**
  - [ ] Расположение и размеры клавиш совпадают с реальной клавиатурой.
  - [ ] Клик по любой назначаемой клавише выбирает её.
  - [ ] В 2D и 3D видны те же состояния.

#### FR-02. 3D-мышь

- **Описание:** справа от клавиатуры — схематичная мышь в тех же цветах. В 3D — с перспективой, объёмной заливкой и затемнением по контуру, в 2D — плоская.
- **Подписи:** вне корпуса, с выносками: слева Mouse 5 и Mouse 4 у боковых кнопок, справа от колеса Mouse wheel up, Mouse 3 и Mouse wheel down.
- **Назначаемые входы:** левая кнопка, правая кнопка, нажатие колеса, прокрутка вверх, прокрутка вниз, боковая кнопка «назад» (Mouse4), боковая кнопка «вперёд» (Mouse5).
- **Поведение:** как у клавиш: выбор, подсветка, цвета категорий, конфликты. Прокрутка вверх и вниз — зоны над и под колесом. Выделенная кнопка обводится по своей части контура обводкой одной толщины; обводка ЛКМ огибает боковые кнопки с зазором.
- **Критерии приёмки:**
  - [ ] Все 7 входов выбираются кликом и принимают бинды.

#### FR-03. Режимы ввода: проверка нажатий и навигация

- **Описание:** переключатель режима ввода в шапке. Работает, когда окно приложения активно и фокус не в поле ввода. При запуске включён режим «Проверка нажатий».
- **Режим «Проверка нажатий»:**
  1. Нажатие настоящей клавиши анимирует её на экране и выделяет её одну.
  2. Нажатие с зажатыми Ctrl, Shift или Alt выделяет клавишу и переключает соответствующий слой.
  3. Модификатор, нажатый и отпущенный без других клавиш, выделяет сам себя (на Ctrl или Shift тоже бывают бинды).
  4. Нажатие колеса, кнопки мыши 4 и 5 и прокрутка над областью клавиатуры и мыши выделяют соответствующий вход. ЛКМ и ПКМ так не выделяются: они заняты выделением и меню.
- **Режим «Навигация»** (как в проводнике):
  - стрелки перемещают выделение на соседнюю клавишу или кнопку мыши по экрану; с правого края клавиатуры стрелка вправо переходит на мышь;
  - Shift+стрелка расширяет выделение в эту сторону;
  - Ctrl+A выделяет все занятые клавиши текущего слоя;
  - клавиши не анимируются и не выделяют сами себя.
- **Мышь** (Ctrl+клик, Shift+клик, рамка) работает одинаково в обоих режимах (FR-13).
- **Ограничения:** не перехватываются комбинации, которые забирает браузер или Windows (Ctrl+W, Ctrl+T, Ctrl+N, Alt+F4). Такие бинды назначаются кликом по экранной клавиатуре. Win и Fn не назначаются вовсе (FR-01). Остальные клавиши получают `preventDefault`, чтобы, например, F5 не перезагружал страницу.
- **Esc** в обоих режимах снимает выделение или закрывает диалог, отменяет захват клавиши.

#### FR-04. Язык подписей EN/RU, EN, RU

- **Режимы** — переключатель в шапке:
  - **EN/RU** — реалистичный вид, как на настоящей клавиатуре: английская подпись слева сверху основным цветом, русская справа снизу серым, на цифрах и символах — верхние символы Shift. Режим по умолчанию.
  - **EN** и **RU** — только то, что нужно для биндов: буквы выбранной раскладки, цифры и клавиши-символы показаны одним знаком по центру (в RU — Й, Х, Ж, Б, Ю, Ё и т. п.), без верхних символов Shift. Модификаторы, F-клавиши и стрелки — в привычном виде.
- **Автопереключение:** кнопка «Авто» рядом с переключателем, по умолчанию включена. В режимах EN и RU раскладка подписей следует за символом последней нажатой клавиши (нажал «й» — включается RU). Режим EN/RU выбирается только вручную и сам не меняется.

- **Действия:** создать, переименовать, удалить (с подтверждением), сменить иконку. Выбор игры — список с иконками в шапке.

#### FR-06. Контексты

- **Описание:** список режимов игры, вводится вручную: название и порядок. Контекст «Везде» системный: его нельзя удалить, он пересекается со всеми.
- **Удаление контекста** с действиями — только с переносом действий в другой контекст.

#### FR-07. Категории с цветом

- **Описание:** список групп действий, вводится вручную: название и цвет (палитра из 12 цветов или свой HEX).
- **Использование:** цвет подкрашивает клавиши и метки действий в панели. Действие может быть без категории (серый цвет).
- **Удаление категории** снимает её с действий после подтверждения.

#### FR-08. Действия

- **Поля:** название (обязательно, до 80 символов), оригинальное название на английском (необязательно), контекст (обязательно, по умолчанию «Везде»), категория, описание (до 300 символов).
- **Список действий:** повторяет меню настроек игры: разделы по категориям в порядке игры, порядок действий и разделов задаётся перетаскиванием, в заготовках — как в игре. В каждой строке — кнопки клавиш для назначения (FR-12). Над списком — поиск.
- **Удаление действия** удаляет его бинды во всех профилях игры, приложение показывает, сколько биндов затронуто.

#### FR-09. Параметр бинда

- **Описание:** у игры может быть один необязательный параметр бинда: название и список значений. Пример для Dota 2: «Режим каста» — «Обычный», «Быстрый», «Быстрый при отпускании».
- **Использование:** при назначении бинда значение выбирается из списка, отображается в панели действий.

#### FR-10. Шаблон настроек

- **Описание:** список настроек игры, общий для всех профилей. Настройки объединяются в группы («Мышь», «Графика», «Звук»).
- **Поля настройки:** группа, название, тип, единица измерения, значение по умолчанию.
- **Типы:**
  - ползунок: минимум, максимум, шаг;
  - переключатель: вкл / выкл;
  - список: варианты значений;
  - текст: до 200 символов.
- **Изменение диапазона** ползунка приводит значения в профилях к новому диапазону, приложение предупреждает об этом.

#### FR-11. Управление профилями

- **Действия:** создать, переименовать, дублировать, удалить (с подтверждением; последний профиль игры удалить нельзя).
- **Поля:** название (1–40 символов, уникальное в игре), заметки (до 1000 символов).
- **Дублирование** копирует бинды, значения настроек и заметки, название — «Копия <имя>».

#### FR-12. Назначение бинда в списке действий

- **Описание:** бинды назначаются как в меню настроек игры: в списке действий у каждого действия есть кнопки клавиш. Число кнопок — по правилу игры (1 или 2). На кнопке — текущая клавиша или комбинация, например «Ctrl+1», или «—», если не назначено.
- **Где:** вкладка «Действия» в панели справа и строки действий в панели выделенной клавиши (FR-13). Поведение кнопки одинаковое.
- **Строка действия:** название, цветная метка категории, контекст, кнопки клавиш, тип нажатия и параметр (выпадающие списки, если отличаются от значения по умолчанию — показываются в строке, иначе в меню «⋯»).
- **Логика:**
  1. Клик по кнопке клавиши переводит её в режим захвата «Нажмите клавишу…», клавиатура на экране подсвечивает это.
  2. Пользователь нажимает клавишу или комбинацию на настоящей клавиатуре, кнопку мыши над изображением мыши или кликает по экранной клавише. Модификаторы берутся из зажатых клавиш.
  3. Проверяются правила игры: допустимые модификаторы. Нарушение — сообщение под кнопкой, бинд не сохраняется.
  4. Проверяются конфликты (FR-15). Конфликт не блокирует: под кнопкой предупреждение со списком пересечений и кнопками «Оставить» и «Снять с других действий».
  5. Бинд сохраняется, подсветка обновляется, данные записываются.
- **Отмена захвата:** Esc или клик вне кнопки. **Снять бинд:** крестик на кнопке.
- **Тип нажатия** (нажатие, удержание, переключение, двойное, долгое; по умолчанию нажатие) и **параметр** (если задан в игре) — свои для каждого бинда.
- **Критерии приёмки:**
  - [ ] Бинд назначается двумя кликами и одним нажатием клавиши.
  - [ ] Кнопок у действия ровно столько, сколько разрешает правило игры.
  - [ ] Комбинация Ctrl+1, нажатая в режиме захвата, сохраняется как Ctrl+1.

#### FR-13. Выделение клавиш и панель действий

- **Выделение мышью** (как в проводнике):
  - клик — выделить одну клавишу или кнопку мыши, остальное снимается;
  - Ctrl+клик — добавить или убрать одну клавишу;
  - Shift+клик — выделить диапазон прямоугольником от последней кликнутой клавиши до текущей: выделяются клавиши, центр которых попадает в прямоугольник (Q → D даёт Q W E A S D);
  - рамка — зажать мышь на пустом месте или на клавише и протянуть, выделяются клавиши и кнопки мыши под рамкой: в 3D — клавиши, верхнюю грань которых задевает рамка (чтобы не цеплять клавиши «позади»), в 2D — по всей клавише; с Ctrl рамка добавляет к выделению. Клик без протягивания выделяет клавишу — по любой её видимой части, включая боковые грани и самый край;
  - клик по пустому месту или Esc — снять выделение.
- **Кнопки мыши** выделяются так же, как клавиши: кликом, Ctrl+кликом, Shift+кликом, рамкой и Shift+стрелками. Для диапазона и стрелок мышь стоит справа от клавиатуры: Shift+клик от Q до левой кнопки мыши захватывает клавиши и кнопки между ними, стрелка вправо с правого края клавиатуры переходит на мышь.
- **Отображение:** выделенные клавиши — толстая обводка акцентного цвета.
- **Панель справа:**
  - одна клавиша — заголовок с клавишей и её действия строками с кнопками клавиш (FR-12), контекст, категория, тип нажатия, параметр, слот; конфликты отмечены красным;
  - несколько клавиш — действия всех выделенных клавиш по группам, плюс кнопка «Создать группу» (FR-29);
  - ничего не выделено — список действий игры с поиском (FR-16) и вкладка «Без клавиши» (FR-17).
- **Ширина панели** 320–480 px, меняется перетаскиванием границы.
- **Критерии приёмки:**
  - [ ] Shift+клик от Q до D выделяет ровно Q W E A S D.
  - [ ] Ctrl+клик по выделенной клавише снимает с неё выделение, не трогая остальные.

#### FR-13. Выбор клавиш и панель действий

#### FR-14. Слои модификаторов

- **Описание:** переключатель слоёв над клавиатурой: «Без модификатора», «Ctrl», «Shift», «Alt» и сочетания, которые используются в профиле. На кнопке слоя — число биндов.
- **Переключение:** кнопками переключателя или нажатием комбинации на настоящей клавиатуре в режиме «Проверка нажатий». Клик по экранным Ctrl, Shift, Alt слой не переключает: он выделяет саму клавишу, потому что на неё тоже бывают бинды.
- **В слое** подсвечены клавиши с биндами этого модификатора, остальные приглушены.
- **Модификаторы** не различаются на левые и правые. Сами клавиши Shift, Ctrl, Alt можно назначать как обычные (например, Shift — «Бег»).

#### FR-15. Конфликты и нарушения правил

- **Конфликт** — два бинда в одном профиле с одинаковыми клавишей, модификаторами и типом нажатия, если их контексты совпадают или один из них «Везде».
- **Не конфликт:** одна клавиша в контекстах «Пешком» и «В транспорте»; одна клавиша с разным типом нажатия.
- **Нарушение правил** — у действия больше клавиш, чем разрешено в игре (например, после смены правила с 2 на 1). Бинды не удаляются, а подсвечиваются.
- **Отображение:** красная обводка клавиши, значок в слое, счётчик в шапке. Клик по счётчику показывает список всех конфликтов и нарушений с переходом к клавише.
- **Пересчёт** при каждом изменении, не дольше 50 мс.

#### FR-16. Поиск действия

- **Описание:** поле поиска над списком действий, по русскому и английскому названию, без учёта регистра.
- **Результат:** список совпадений; наведение или клик по действию подсвечивает его клавиши, остальные приглушаются, слой переключается при необходимости.

#### FR-17. Неназначенные действия

- **Описание:** вкладка «Без клавиши» со списком действий игры без бинда в текущем профиле, с кнопкой «Назначить клавишу» у каждого.

#### FR-18. Значения настроек с ползунками

- **Где:** вкладка «Настройки» в панели профиля.
- **Отображение:** группы как в шаблоне. Ползунок с полем для точного значения рядом, переключатели, списки, текст. У значения, отличного от значения по умолчанию, есть кнопка сброса.
- **Валидация:** число вне диапазона в поле приводится к ближайшей границе с подсказкой «Допустимо от … до …». Значение округляется до шага.
- **Критерии приёмки:**
  - [ ] Ползунок и поле синхронизированы в обе стороны.
  - [ ] Значения сохраняются отдельно для каждого профиля.

#### FR-19. Папка данных и автосохранение

- **Первый запуск:** выбор папки (сценарий 1). Ссылка на папку хранится в IndexedDB, при следующих запусках выбор не нужен.
- **Структура папки:** `data.json` — все данные; `icons/` — иконки игр; `backups/` — резервные копии.
- **Автосохранение:** через 1 секунду после последнего изменения. В шапке статус: «Сохранено», «Сохранение…», «Ошибка сохранения».
- **Разрешение:** если браузер снова спрашивает доступ, показывается экран «Разрешить доступ к папке» с кнопкой. Совет выбрать «Разрешать при каждом посещении».
- **Смена папки** — в настройках приложения, с переносом данных или открытием существующих.

#### FR-20. Резервные копии

- **Когда:** при каждом запуске, перед записью первого изменения — копия `data.json` в `backups/` с датой и временем в имени.
- **Хранится** 5 последних, старые удаляются.
- **Восстановление:** список копий в настройках, кнопка «Восстановить» с подтверждением; текущее состояние перед этим тоже сохраняется в копию.

#### FR-21. Импорт и экспорт

- **Экспорт:** всё, одна игра или один профиль. Файл `*.hotkeymap.json`, иконки встроены в файл.
- **Импорт:**
  1. Выбрать файл или перетащить его в окно.
  2. Проверить схему и версию. Ошибки показываются списком, импорт не выполняется.
  3. Показать предпросмотр: что добавится, что совпадает.
  4. При совпадении игры или профиля предложить: объединить, создать копию или заменить.
- **Критерии приёмки:**
  - [ ] Экспорт всего и импорт в чистое приложение восстанавливают данные полностью.
  - [ ] Повреждённый файл не меняет текущие данные.

#### FR-22. Заготовки Dota 2 и PUBG

- **Описание:** готовые файлы импорта в репозитории с действиями, контекстами, категориями, параметром бинда и шаблоном настроек по актуальному меню игр. Названия на русском, как в русском клиенте, с английским оригиналом. Биндов в заготовках нет, только справочники.
- **Где:** предложение при первом запуске и кнопка «Добавить из заготовок» при создании игры.
- **Правила:** Dota 2 — 1 клавиша на действие, параметр «Режим каста». PUBG — 2 клавиши на действие, контексты для разных режимов (пешком, транспорт, парашют и т. п.).

#### FR-23. Запасной режим Firefox

- **Описание:** если File System Access API недоступен, данные хранятся в IndexedDB. Вверху постоянная плашка: «Данные хранятся в браузере. Для хранения в папке откройте в Chrome или Edge».
- **Напоминание** сделать экспорт, если последнего экспорта не было 7 дней.

#### FR-24. Отмена и повтор

- **Описание:** кнопки «Отменить» и «Повторить» в шапке, история 50 шагов в пределах сессии. После удаления — всплывающее сообщение с кнопкой «Отменить».

#### FR-25. Темы

- **Варианты:** системная (по умолчанию), светлая, тёмная. Переключатель в шапке, выбор запоминается.

#### FR-26. Подписи действий на клавишах

- **Описание:** переключатель «Подписи на клавишах». Включено — короткое название первого действия на клавише (до 10 символов, остальное многоточием) и число «+N», если действий больше. Выключено — только подсветка цветом. По умолчанию включено.

#### FR-27. Защита от двух вкладок

- **Описание:** вторая открытая вкладка определяет первую (BroadcastChannel) и работает только для просмотра с плашкой «Приложение уже открыто в другой вкладке».

#### FR-28. Обновление PWA

- **Описание:** при выходе новой версии — плашка «Доступна новая версия» с кнопкой «Обновить».

#### FR-29. Группы клавиш

- **Описание:** пользователь объединяет клавиши в именованные группы с цветом, например «Под левой рукой» или «Способности». Группы относятся к профилю.
- **Создание:** выделить клавиши (FR-13) → «Создать группу» в панели → название (1–40 символов) и цвет из палитры или HEX.
- **Правила:** клавиша входит не больше чем в одну группу. Если выделенная клавиша уже в другой группе, приложение спрашивает, перенести ли её.
- **Управление:** список групп во вкладке «Группы» панели: переименовать, сменить цвет, добавить или убрать выделенные клавиши, удалить, скопировать в другой профиль.
- **Критерии приёмки:**
  - [ ] Клавишу нельзя добавить в две группы одновременно.
  - [ ] Группа копируется в другой профиль этой игры.

#### FR-30. Режим окраски

- **Описание:** переключатель в шапке рядом со слоями: «По категориям» или «По группам». Цвета не смешиваются.
- **По категориям:** клавиша заливается цветом категории первого действия, при нескольких категориях — полосками цветов.
- **По группам:** клавиша заливается цветом своей группы, клавиши вне групп нейтральные. Категории действий видны цветной меткой в панели справа.
- **Выделение и конфликты** в обоих режимах показываются обводкой: акцентной и красной со значком.
- **По умолчанию:** «По категориям», выбор запоминается.

## 8. Интерфейс и UX

### 8.1. Карта экранов и навигация

Приложение одноэкранное: всё основное на главном экране, редактирование — в боковых панелях и диалогах.

- **Первый запуск** → выбор папки → предложение заготовок → **Главный экран**.
- **Главный экран:**
  - шапка → **Редактор игры**, **Импорт и экспорт**, **Настройки приложения**;
  - панель справа → вкладки **Действия**, **Без клавиши**, Группы, **Настройки профиля**, **Заметки**;
  - выбор клавиши → панель действий клавиши → **Диалог назначения бинда**;
  - счётчик конфликтов → **Список конфликтов**.

- Клавиша без биндов: «На клавише ничего нет» и кнопка «Назначить действие».

### 8.3. Визуальный стиль

- **Общий стиль:** минималистичный, «игровой», без лишних украшений. Клавиатура — главный визуальный объект.
- **Цвета:** нейтральные фон и корпус клавиатуры, акцентный цвет для выбора, красный для конфликтов, цвета категорий задаёт пользователь. Все цвета — CSS-переменные для тем.
- **Шрифты:** Inter для интерфейса; шрифт и размеры подписей на клавишах задаёт тема устройств (`legend` в `device-theme.ts`).
- **Темы:** системная, светлая, тёмная.
- **Иконки:** lucide-react.
- **3D:** перспектива и наклон из темы устройств (клавиатура 32°, мышь 16° с более сильной перспективой), мягкие тени, у клавиш видны верхняя, передняя и внутренняя боковая грани.

### 8.4. Адаптивность и размеры окна

- Минимальный размер окна 1280×720, меньше — горизонтальная прокрутка.
- Клавиатура и мышь масштабируются по ширине центральной области.
- Панель справа меняет ширину в пределах 320–480 px.
- Окно PWA запоминает размер и положение (средствами браузера).

### 8.5. Управление и доступность

- **Мышь:** клик, Ctrl+клик, Shift+клик, рамка — как в проводнике, для клавиш и кнопок мыши (FR-13).
- **Клавиатура в режиме «Проверка нажатий»:** нажатия выделяют нажатые клавиши (FR-03); Esc снимает выделение или закрывает диалог.
- **Клавиатура в режиме «Навигация»:** стрелки, Shift+стрелки, Ctrl+A, Esc.
- **Действия приложения** (отмена, экспорт и т. п.) — кнопками, без горячих клавиш, чтобы не мешать проверке биндов.
- **Доступность:** диалоги и формы полностью управляются с клавиатуры, контраст текста не ниже 4.5:1, категория показывается не только цветом, но и названием в панели.

### 8.6. Тексты и язык интерфейса

- **Язык интерфейса:** русский. Все строки в одном файле `src/i18n/ru.ts`, чтобы позже добавить другие языки.
- **Подписи клавиш:** английские и русские, активный язык ярче (FR-04).
- **Тон:** на «вы», коротко и по делу.
- **Форматы:** дата ДД.ММ.ГГГГ, время ЧЧ:ММ, десятичный разделитель — запятая.

## 9. Данные и хранение

### 9.1. Сущности и модель данных

Все идентификаторы — UUID (`crypto.randomUUID()`). У сущностей верхнего уровня есть поля `createdAt` и `updatedAt` в формате ISO 8601.

**AppData** — корень файла `data.json`

| Поле | Тип | Описание |
| --- | --- | --- |
| schemaVersion | Integer | Версия схемы данных, начиная с 1 |
| games | Game\[\] | Игры |
| appSettings | Object | Тема, язык подписей, 2D / 3D, подписи на клавишах, режим окраски, режим ввода, последняя открытая игра и профиль |

**Game** — игра

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| id, name | UUID, String | Да | Идентификатор и название |
| icon | String | Нет | Имя файла в `icons/` |
| steamAppId | Integer | Нет | AppID в Steam |
| rules | Object | Да | `maxKeysPerAction`: 1 или 2; `allowedModifiers`: набор из ctrl, shift, alt; `blockedKeys`: коды клавиш, которые не передаются в игру (по умолчанию Fn, Win, регулятор) |
| contexts | Context\[\] | Да | Контексты, всегда содержит системный «Везде» |
| categories | Category\[\] | Да | Категории |
| actions | Action\[\] | Да | Действия |
| bindParam | BindParam | Нет | Параметр бинда |
| settingsTemplate | SettingDef\[\] | Да | Шаблон настроек |
| profiles | Profile\[\] | Да | Профили, минимум один |

**Вложенные сущности**

| Сущность | Поля |
| --- | --- |
| Context | id, name, isGlobal (true только у «Везде»), order |
| Category | id, name, color (HEX) |
| Action | id, name, nameEn?, contextId, categoryId?, description?, order |
| BindParam | name, options: { id, name }\[\] |
| SettingDef | id, group, name, type (slider, toggle, select, text), unit?, min?, max?, step?, options?, defaultValue, order |
| Profile | id, name, notes, bindings: Binding\[\], settingValues: { settingId: value }, keyGroups: KeyGroup\[\] |
| Binding | id, actionId, input: { device (keyboard, mouse), code, modifiers }, pressType (press, hold, toggle, double, long), paramOptionId?, slot (1 или 2) |
| KeyGroup | id, name, color (HEX), inputs: коды входов\[\]; один вход — не больше чем в одной группе профиля |

Коды входов: для клавиатуры — значения `KeyboardEvent.code` (`KeyQ`, `Digit1`, `ShiftLeft`); для мыши — `MouseLeft`, `MouseRight`, `MouseMiddle`, `WheelUp`, `WheelDown`, `Mouse4`, `Mouse5`.

### 9.2. Связи между сущностями

- Игра 1 — N контексты, категории, действия, настройки шаблона, профили.
- Профиль 1 — N бинды. Бинд ссылается на действие той же игры.
- Действие N — 1 контекст, N — 0..1 категория.
- **Удаление:** игры — со всеми данными; действия — с его биндами во всех профилях; категории — снимается с действий; контекста — только с переносом действий; настройки шаблона — значения удаляются из профилей. Каждое удаление с подтверждением и числом затронутых записей.

### 9.3. Хранение

| Параметр | Значение |
| --- | --- |
| Где хранятся данные | Папка на диске, выбранная пользователем (File System Access API). В режиме Firefox — IndexedDB |
| Состав папки | `data.json`, `icons/`, `backups/` |
| Ожидаемый объём | До 2 МБ `data.json`, иконки до 50 КБ каждая |
| Запись | Через 1 с после последнего изменения, целиком файл |
| Резервные копии | При каждом запуске, 5 последних (FR-20) |
| Срок хранения | Бессрочно |
| Миграции схемы | При загрузке: если `schemaVersion` меньше текущей — последовательные функции миграции, перед миграцией — резервная копия. Если больше — сообщение «Данные созданы более новой версией приложения, обновите страницу» |

### 9.4. Импорт и экспорт

| Направление | Формат | Что переносится | Примечания |
| --- | --- | --- | --- |
| Экспорт | `*.hotkeymap.json` | Всё, одна игра или один профиль | UTF-8, иконки внутри файла в Base64, поля `schemaVersion`, `scope`, `exportedAt` |
| Импорт | `*.hotkeymap.json` | То же | Проверка схемой Zod, предпросмотр, стратегии: объединить, копия, заменить; лимит 20 МБ |

Совместимость с файлами конфигов игр — этап 2.

### 9.5. Справочники и начальные данные

- **В каждой новой игре:** контекст «Везде», профиль «Основной».
- **Раскладка клавиатуры:** AULA F75 (приложение А), раскладка мыши с 7 входами.
- **Заготовки:** `src/presets/dota2.json` и `src/presets/pubg.json` — действия, контексты, категории с цветами, параметр бинда, шаблон настроек. Составляются по актуальному меню игр при разработке.
- **Палитра категорий:** 12 предустановленных цветов, различимых в обеих темах.
- **Пример структуры данных** — приложение Б.

## 13. Ошибки и граничные случаи

### 13.1. Обработка ошибок

| Ситуация | Что видит пользователь | Что делает система |
| --- | --- | --- |
| Неверные данные в форме | Поле подсвечено, под ним причина; кнопка «Сохранить» неактивна | Не сохраняет |
| Браузер не поддерживает доступ к файлам | Плашка про запасной режим (FR-23) | Переключается на IndexedDB |
| Нет разрешения на папку | Экран «Разрешить доступ к папке» с кнопкой | Ждёт разрешения, данные не теряются: изменения держатся в памяти |
| Папка удалена или перемещена | «Папка данных не найдена» и кнопки «Выбрать папку» и «Создать новую» | Предлагает выбрать заново |
| `data.json` повреждён | «Файл данных повреждён» и список резервных копий | Не перезаписывает файл, предлагает восстановление |
| Ошибка записи на диск | Плашка «Не удалось сохранить» с кнопкой «Повторить» | Повторяет попытку через 5 с, до 3 раз |
| Файл импорта неверный | Список ошибок с понятным описанием | Не меняет текущие данные |
| Данные новее версии приложения | «Данные созданы более новой версией, обновите страницу» | Не открывает данные на запись |
| Не загрузилась иконка Steam | «Не удалось загрузить иконку» | Предлагает картинку вручную |
| Неожиданная ошибка интерфейса | «Что-то пошло не так» и кнопка «Перезагрузить» | Error Boundary, подробности в консоль, данные в файле не трогаются |

### 13.2. Граничные случаи

- Комбинация, которую перехватывает браузер или Windows (Ctrl+W, Alt+F4) → не ловится нажатием, назначается кликом.
- Fn, Win и регулятор (и другие непередаваемые клавиши игры) → не назначаются; пока зажата кнопка мыши, видны вспышка отказа и подсказка «Эта клавиша не передаётся в <игра>» (FR-01).
- Включена русская раскладка ввода → клавиши определяются по физическому коду, бинды работают так же.
- Действие удаляется, а у него бинды в нескольких профилях → подтверждение с числом биндов.
- Правило «клавиш на действие» меняется с 2 на 1 → лишние бинды не удаляются, а отмечаются как нарушение.
- Удаляется модификатор из допустимых → бинды с ним отмечаются как нарушение.
- Удаление последнего профиля → запрещено.
- Двойной клик по «Сохранить» → создаётся одна запись, кнопка блокируется на время сохранения.
- Длинные названия → обрезаются многоточием на клавише и в списках, полностью видны в подсказке.
- На клавише 10 и больше действий → панель прокручивается, на клавише «+N».
- В поле ползунка вводится значение вне диапазона или не число → приводится к границе или к прежнему значению с подсказкой.
- Импорт игры с таким же id или названием → диалог стратегии (объединить, копия, заменить).
- Вторая вкладка → режим только для просмотра (FR-27).
- Окно меньше 1280×720 → появляется прокрутка, интерфейс не ломается.

### 13.3. Логирование

- **Что:** ошибки хранения, импорта и интерфейса.
- **Где:** консоль браузера. Внешние сервисы мониторинга не используются.
- **Срок хранения:** не хранится.

## 15. Сборка, развёртывание и обновления

### 15.1. Окружения

| Окружение | Назначение | Где работает | Данные |
| --- | --- | --- | --- |
| Разработка | Написание и отладка кода | `localhost:5173`, команда `npm run dev` | Отдельная тестовая папка данных |
| Продакшн | Ежедневное использование | GitHub Pages, установлено как PWA | Реальная папка данных |

Локальный адрес и GitHub Pages — разные сайты, у каждого своё разрешение на папку. Для разработки выбирается отдельная папка, чтобы не задеть реальные данные.

### 15.2. Сборка и выпуск

- **Сборка:** `npm run build`, результат — статические файлы в `dist/`.
- **CI/CD (GitHub Actions):**
  - на каждый push и pull request — линтер, проверка типов, тесты;
  - на push в `main` — дополнительно сборка и публикация на GitHub Pages.
- **Версии:** SemVer, тег `v1.0.0` — MVP. Номер версии виден в настройках приложения.

### 15.3. Установка и первый запуск

1. Открыть адрес приложения на GitHub Pages в Chrome или Edge.
2. Нажать значок установки в адресной строке — появится ярлык на рабочем столе.
3. Выбрать папку данных и разрешить доступ «при каждом посещении».
4. Загрузить заготовки Dota 2 и PUBG или начать с нуля.

### 15.4. Обновления

- **Доставка:** автоматически после публикации, плашка «Доступна новая версия» (FR-28).
- **Совместимость данных:** миграции схемы при загрузке, резервная копия перед миграцией.
- **Откат:** `git revert` проблемного коммита и повторная публикация; данные восстанавливаются из резервной копии.

### 15.5. Поддержка

- Ошибки и идеи — в Issues репозитория на GitHub.
- Мониторинг не нужен: приложение работает целиком в браузере.

| 6 | Left Ctrl, Win, Left Alt, пробел, Fn (1.25u), Right Ctrl (1.25u), зазор 0.5u, ←, ↓, → |

Fn, Win и регулятор отображаются, но не назначаются.
